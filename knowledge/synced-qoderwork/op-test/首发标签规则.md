# 原创保护-首发标签规则

首发标是商品获得 302 高档补贴的关键标志，规则复杂涉及 5 种时间组合 + T+3/T+4 编辑窗口期。

## 5 种时间组合

首发判断依赖以下 4 个时间字段：

| 字段 | 含义 |
|------|------|
| patent_apply_time | 专利申请时间（用户提交时间） |
| patent_grant_time | 专利授权时间 |
| product_publish_time | 商品上架时间 |
| product_launch_time | 商品首次销售时间 |

### 5 种合法组合

| 组合 | 时序 | 是否首发 | 测试场景 |
|------|------|---------|---------|
| A | 专利申请 < 商品上架 < 商品销售 < 专利授权 | ✅ 首发 | 标准首发流程 |
| B | 专利申请 < 商品上架 < 专利授权 < 商品销售 | ✅ 首发 | 授权后销售 |
| C | 专利申请 < 专利授权 < 商品上架 < 商品销售 | ❌ 非首发 | 授权后才上架 |
| D | 商品上架 < 专利申请 < 商品销售 < 专利授权 | ❌ 非首发 | 商品先于专利 |
| E | 商品上架 < 商品销售 < 专利申请 < 专利授权 | ❌ 非首发 | 销售后才申请专利 |

### 核心判断规则

```
是否首发 = (patent_apply_time < product_publish_time)
       AND (patent_apply_time < product_launch_time)
```

通俗：**专利申请必须早于商品上架和销售**。

## T+3 / T+4 编辑窗口期

### T+3：商家自助修改窗口

- 商品上架后 3 天内，商家可修改首发标信息
- 超过 T+3，进入 T+4 阶段

### T+4：小二审核窗口

- 商家不可修改，但小二可后台修改
- 超过 T+4，首发标"锁定"，需走专项审批

### 边界测试

| 场景 | 时刻 | 预期 |
|------|------|------|
| T+0 商家编辑 | 上架后 0 小时 | ✅ 允许 |
| T+2 23:59 商家编辑 | 上架后 71h59m | ✅ 允许 |
| T+3 00:00 商家编辑 | 上架后 72h00m | ❌ 拒绝 |
| T+3 00:00 小二编辑 | 上架后 72h00m | ✅ 允许（T+4 窗口） |
| T+4 00:00 小二编辑 | 上架后 96h00m | ❌ 拒绝（需专项审批） |
| T+4 00:00 专项审批 | 上架后 96h00m | ✅ 允许 |

## 首发标到期摘除（FirstLaunchExpireJob）

### 到期时间计算

```
first_launch_expire_time = product_launch_time + 首发期时长
```

首发期时长由专利类型决定：
- 外观专利：6 个月
- 实用新型：1 年
- 发明专利：3 年

### 摘标流程

```
FirstLaunchExpireJob（每日 03:00）
  → 查询所有 first_launch_expire_time < now() 且 first_launch_status=ACTIVE 的商品
  → 调用商品中台摘除标签
  → 更新 first_launch_status = EXPIRED
  → MetaQ 通知商家
```

### 边界测试

| 场景 | 时刻 | 预期 |
|------|------|------|
| 到期前 1 秒 | expire_time - 1s | first_launch_status=ACTIVE |
| 到期当天 03:00 任务前 | 03:00:00 之前 | first_launch_status=ACTIVE |
| 到期当天 03:00 任务后 | 03:00:01 之后 | first_launch_status=EXPIRED |
| 任务漏跑 | 03:00 任务未执行 | 次日 03:00 补跑 |

## 禁发期规则

### 触发禁发期场景

1. **专利被驳回**：3 个月内不可再申请同类专利
2. **维权失败**（误报）：6 个月内不可对该商品维权
3. **违规摘标**：1 年内该商家不可再申请首发

### 禁发期记录表
```sql

  id BIGINT,

  end_time DATETIME,
  reason VARCHAR(256)
);
```

## 是否首发标签编辑规则（实际实现）

> 来源: doc2(白名单url及是否首发规则优化) + doc5(运营后台)

**核心原则**: 必须有商品确认一致性时间才能编辑"是否首发"标签。

### 编辑规则（基于 2 个时间字段）

| 字段 | 含义 |
|------|------|
| 首次上架时间 | 商品首次从仓库上架到前台的时间 |
| 商品确认一致性时间 | YC 确认商品与专利一致的时间 |

#### 5 种时间组合与编辑性

| # | 首次上架时间 | 确认一致性时间 | 基准时间 | 是否可编辑 |
|---|-------------|---------------|---------|-----------|
| 1 | 空 | 空 | 无 | ❌ 不可编辑 |
| 2 | 有 | 空 | 无 | ❌ 不可编辑 |
| 3 | 空 | 有 | 确认一致性时间 | ✅ 以确认一致性时间判断 |
| 4 | 有 | 有 | min(两者) | ✅ 以较早时间判断 |

#### 编辑窗口期

- **T+3天内**: 可编辑是否首发标签
- **T+4天0:00后**:
  - 如果**已编辑过** → ❌ 锁定，不可再编辑
  - 如果**从未编辑过** → ✅ 允许编辑一次
- **一致性确认后**: 标签不可变

### 运营后台编辑规则（doc5）

- 小二后台首发标签: 下拉单选(是/否)，可编辑
- 编辑窗口: 商品首次上架时间后3天内，第4天0点后不可修改
- icon提示: "该商品首次上架日期为XXXX年-XX月-XX日，您可在XXXX年-XX月-XX+4日前修改标签"
- 仓库中商品: 不可确认一致性
- 绑定不一致时: 是否首发不可操作，需重新绑定后才能操作
- 第4天0点后: 若商品还没确认一致性或没有首发标签，暂不退；后续一致性检验不通过则清空标签

## 已知陷阱

1. **跨年时区问题**：使用 UTC+8 北京时间，存储用 UTC 转换
2. **闰年 2/29**：申请时间为 2/29 时续期跨年的处理
3. **商家时区差异**：海外商家时间字段以提交方时区为准还是平台时区？需明确
4. **publish_time vs launch_time 顺序倒置**：业务上 publish 应早于 launch，但实际数据可能倒置
5. **expire_time 计算**：`launch_time + 首发期时长` 而非 `apply_time + 时长`
6. **编辑规则与判断规则分离**："是否首发"的判断(5种时间组合)与"是否可编辑"(基于确认一致性时间)是两套独立逻辑
7. **T+4未编辑过一次机会**：T+4后从未编辑过的商家可编辑一次，编辑后即锁定，需精确验证"是否编辑过"的状态
8. **一致性失败清空标签**：商品一致性检验不通过时，关联商品和首发标签都清掉，商家需重新绑定
