### 关键流转规则

1. **快审/初审/普通三种模式分支**（DRAFT → SUBMITTED 后路径不同）：
   - 快审：T+3 工作日，跳过 EXAM 直接 GRANTED
   - 初审：T+15，正常流程
   - 普通：T+30，正常流程

2. **不可逆终态**：ARCHIVED, REVOKED 后不可回退

3. **转正/转普通状态机独立**：to_regular_status 是独立字段，不影响主状态
   - 已沉淀MEMORY：是否首发的可编辑性由业务生命周期控制，非 to_regular_status 直接决定
   - to_regular_status 非空时下拉框禁用
   - 转普通(to_regular)流程：驳回 → TO_DO → DONE/TIMEOUT，详见「转普通申请状态流转」章节

4. **冻结状态全局阻塞**：FROZEN 时不可绑定/维权/结算

### 草稿态(DRAFT)补充规则（doc3 实际测试）

- **草稿不占用权益**，不在权益计算中
- 但**没有权益时不能新建草稿**（开发加了校验）
- saveOrApply 参数: save=保存草稿, apply=提交申请, 不传=补充材料
- 列表状态tab新增【草稿中】+ 蓝色标签
- 运营后台申请状态选项增加筛选项【草稿中】

### 取消申请规则（doc3）

- **初审通过前**: 商家可自行取消（退权益+1），底部显示「取消申请」按钮
- 点击后二次确认即终止并返回服务次数
- 初审补充材料时也可撤销申请
- **初审通过后**: 仅YC可取消
- 取消申请后权益数应+1（验证: 取消前18→取消后19）

### 时间轴展示规则（doc3）

- **初审中被下补件时**: 还未到第二个节点，文案应**置灰**且去掉「中」字
- 实际实现: 初审中节点加粗显示（需改为置灰）
- 待补充材料状态: 增加查看附件内容并支持下载

### 转普通申请状态流转 [需求#83163231]

**触发条件**: 仅以下驳回状态会触发转普通申请建议:
- PRE_PRE_AUDIT_REJECT (初审驳回)
- PRE_AUDIT_REJECT (预审驳回)
- CERT_REJECT (认证驳回)
- 注意: QUICK_REJECT (快审驳回) 不触发转普通

**to_regular_status 状态流转**:
```
驳回 → 后端写入 to_regular_status=TO_DO + to_regular_suggest_time=当前时间
  ├── 商家点击"提交普通申请"确认 → TO_DO → DONE → 进入普通申请流程
  ├── 3天内未操作 → TO_DO → TIMEOUT (定时任务自动失效)
  └── 按钮不展示(非TO_DO状态) → 无操作
```

**前端入口条件**: `renderNormalApplyEntry()` 检查 `patentDetail?.toRegularStatus !== 'TO_DO'` 时返回 null (不展示按钮)

**超时机制**: Diamond 配置 TO_REGULAR_TIMEOUT_DAYS (默认3天)，ScheduleX 定时任务扫描 to_regular_suggest_time 超过阈值的 TO_DO 记录并更新为 TIMEOUT

**已验证的状态路径** (seller_id=2213249110271):
- 200000720: PRE_PRE_AUDIT_REJECT → TO_DO → DONE → CERT_FILE_SYNCED ✓
- 200000722: PRE_AUDIT_REJECT → TO_DO → TIMEOUT ✓
- 200000530: PRE_PRE_AUDIT_REJECT → TO_DO → TIMEOUT (suggest_time=06-15 11:07) ✓

## 状态机校验测试模板（pytest）

```python
import pytest
from typing import Set

# 状态机定义
APPLY_TRANSITIONS = {
    "DRAFT": {"SUBMITTED", "WITHDRAWN"},
    "SUBMITTED": {"PRE_REVIEWING", "WITHDRAWN"},
    "PRE_REVIEWING": {"PRE_APPROVED", "PRE_REJECTED"},
    # ... 完整状态图
    "ARCHIVED": set(),  # 终态
}

@pytest.mark.parametrize("from_state, to_state, should_pass", [
    ("DRAFT", "SUBMITTED", True),
    ("DRAFT", "GRANTED", False),  # 非法跳转
    ("ARCHIVED", "DRAFT", False),  # 终态不可回退
    ("PRE_REJECTED", "DRAFT", True),  # 驳回后可重编辑
])
def test_state_transition(api_client, from_state, to_state, should_pass):
    apply_id = setup_apply_in_state(from_state)
    response = api_client.transition(apply_id, to_state)
    if should_pass:
        assert response.status_code == 200
        assert query_db(f"SELECT status FROM yc_right_apply WHERE id={apply_id}") == to_state
    else:
        assert response.status_code in [400, 403]
        assert query_db(f"SELECT status FROM yc_right_apply WHERE id={apply_id}") == from_state
```
