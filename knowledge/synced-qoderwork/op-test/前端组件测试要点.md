# 原创保护-前端组件测试要点

## 商家端核心组件 (industry-source-code/original-protection)

技术栈：ICE.js 3.x + React + Ant Design

### 1. ContractPage（签约页面）

- 入口：`/contract` 千牛白名单 TTYCBH
- 关键交互：
  - 是否签约接口 `/api/sign/check` → 已签约直接跳转专利申请；未签约展示签约协议
  - 签约提交 → MetaQ 异步存证（区块链上链，非同步）
- 测试要点：
  - 重复签约校验：已签约用户不应展示签约页
  - 签约协议版本号必须随更新变化
  - 存证失败需要兜底重试逻辑
  - 千牛免登态过期时跳转登录

### 2. PatentApply（专利申请页面）

三种申请模式 + 五个阶段时间轴。

#### 三种申请模式

| 模式 | 关键字段 | 时间约束 | 测试场景 |
|------|---------|---------|---------|
| 快审（fastReview） | 模板分类必填、首发时间不可超过未来3个月 | T+3 工作日 | 上传图片≥3张校验、模板分类下拉是否异步加载 |
| 初审（preReview） | 设计图/产品图必填 | T+15 工作日 | 文件大小限制（单图≤5MB）、文件格式校验 |
| 普通（normal） | 描述文字≥50字 | T+30 工作日 | 描述字数实时校验、提交后状态置为 pending |

测试时务必覆盖**三种模式的字段必填差异** —— UI 表单 schema 是动态切换，容易出现"切换模式后旧数据残留"。

#### 五个阶段时间轴（PatentDetail 页面）

```
申请提交 → 受理 → 实审 → 授权 → 公告
```

每个阶段显示状态点 + 时间戳 + 关联文件。

- 测试要点：
  - 当前阶段高亮颜色与历史阶段区分
  - 阶段倒退（如驳回回到初审）时间轴是否正确渲染
  - 文件下载链接 OSS 鉴权过期处理
  - 移动端竖向时间轴布局回归

### 3. BindProductModal（绑定商品弹窗）

两个 Tab：**已绑定** / **可绑定**。

- **已绑定 Tab**：
  - 列表展示当前 SKU 已绑定的专利列表
  - 解绑操作触发二次确认 + MetaQ 异步消息（解绑后维权能力立即下线）
  - 分页：默认 20 条/页

- **可绑定 Tab**：
  - 仅展示当前用户名下"已授权"专利
  - 多选 + 批量绑定（一次最多绑定 50 个 SKU）
  - 绑定上限校验：单专利绑定 SKU 总数 ≤ 100

- 测试要点：
  - 跨 Tab 切换数据是否丢失
  - 已绑定专利不应出现在可绑定 Tab
  - 批量绑定部分失败时，UI 错误提示是否精确到 SKU
  - 绑定后小二端 g_strategy 状态同步延迟（MetaQ 通常 < 3s）

### 4. InspectionDetail（抽检详情页）

抽检场景的下架率展示（饼图）。

- 关键展示：
  - 总样本数 / 下架样本数 / 下架率
  - 饼图分区：已下架（红）/ 未下架（绿）/ 申诉中（黄）
  - 下架率 ≥ 70% 触发"建议批量下架"按钮

- 测试要点：
  - 下架率精度：保留两位小数（70.00% 不应显示为 70%）
  - 饼图响应式：小屏幕降级为环形图
  - 申诉中样本计入分母不计入分子
  - "建议批量下架"按钮仅在下架率 ≥ 70% 时出现，按钮触发后调用维权接口

### 5. ContractRenewal（续签页面）

- 到期前 30 天自动出现续签入口
- 续签后专利续费 + 补贴重新计算

测试要点：
- 续签前后 yc_right_apply.expire_time 字段是否正确更新
- 续签失败回滚（避免扣费但未续签）

## 小二端核心组件 (bzb-westeros/taotian-apparel-original-protection-xiaoer)

技术栈：icestark 微前端子应用 + React + Ant Design Pro

### 1. RightListPage（权利列表页）

- 路径：`/bzb/noone/taotian-apparel-original-protection-xiaoer/list`
- 数据源：`bzb.api.sceneplatform.tbyc.right.page`
- 列字段：申请ID / 卖家ID / 申请类型 / 当前状态 / 是否首发 / 创建时间 / 操作

- 测试要点：
  - icestark 子应用切换时路由参数保留
  - 状态筛选：21 个申请状态全部覆盖
  - "是否首发"列编辑性：to_regular_status 非空时下拉框禁用（已沉淀 MEMORY）
  - tooltip 触发目标为帮助图标（aria-describedby），非文字链接
  - 大数据量分页（≥10000 条）滚动性能

### 2. PatentReviewPanel（专利审核面板）

小二审核操作的核心面板。

- 操作：**通过 / 驳回 / 转人工**
- 驳回必填驳回原因（下拉 + 自定义文本）
- 转人工进入工单流转

测试要点：
- 操作权限校验（普通小二无转人工权限）
- 驳回原因下拉非空校验（前端阻塞 + 后端二次校验）
- 操作日志记录到 yc_right_op_log（含操作人花名）
- 多次重复点击防抖

### 3. SettleApplyTable（结算申请审核）

- 数据源：yc_right_settle_order
- 字段：订单ID / SKU数 / 应结算金额 / 补贴金额 / 状态 / 操作

测试要点：
- 应结算金额计算公式：500 × SKU 数 + 补贴
- 补贴判断：是否首发决定 302/202 档位
- 官费 165 是否扣减（非首发不扣）
- 70% 下架率阈值校验（结算前置条件）

### 4. ToRegularStatusEditor（转正状态编辑器）

- 字段：to_regular_status（枚举：未转正 / 转正中 / 已转正 / 不予转正）
- 编辑约束：业务生命周期控制，非 to_regular_status 直接决定（已沉淀 MEMORY）

测试要点：
- 状态机转换合法性
- 非合法跳转 UI 阻塞（如已转正不可回退到未转正）
- 编辑后操作日志记录

## 通用组件踩坑（F88经验复用）

| 踩坑 | 描述 | 测试方法 |
|------|------|---------|
| Tooltip 目标错位 | 帮助图标 aria-describedby 才是真实目标，文字 hover 不触发 | 用 `aria-describedby` 定位 |
| Antd Button dispatchEvent 失效 | React 合成事件不响应 dispatchEvent('click')，需用 computer 工具坐标点击 | computer.left_click(x, y) |
| icestark 子应用刷新丢失路由参数 | 父应用路由跳转后子应用未保留 query | 使用 history.push 显式带 query |
| Antd Form 切换 schema 残留 | 动态字段切换时旧值未清理 | form.resetFields() 后再切换 |
| 文件上传跨域 | OSS 直传需 CORS 配置，预发与生产 endpoint 不同 | 校验 Network 面板 OPTIONS 请求 |

## React Fiber 数据提取（无 API 时备选）

```javascript
// 主任务页提取子任务数据（替代 task/sub/detail API）
const fiber = document.querySelector('[data-task-id]')._reactFiber$xxx;
function findHistory(fiber, depth = 0) {
  if (depth > 10) return null;
  if (fiber.memoizedProps?.history) return fiber.memoizedProps.history;
  return findHistory(fiber.child, depth + 1) || findHistory(fiber.sibling, depth);
}
```

注：Fiber key 动态变化（`__reactContainer$*`），需遍历 child 找 memoizedProps.history（depth 通常在 7）。
