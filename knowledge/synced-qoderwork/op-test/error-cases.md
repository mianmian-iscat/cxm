# 打标错误场景速查

参考钉钉文档：https://alidocs.dingtalk.com/i/nodes/XPwkYGxZV347LdvpH6ZEyr1xJAgozOKL?utm_scene=team_space

## 场景一：文档格式有问题

**现象**：上传后报错"文档格式不正确"

**错误示例**：
- 上传了 `.docx` / `.csv` / `.xlsx` 等非 TXT 文件
- TXT 文件包含 BOM（UTF-8 with BOM）
- TXT 文件用了 Windows 换行符 `\r\n`（部分情况下不被识别）

**解决方案**：使用本 skill 生成的标准 `.txt`（UTF-8 无 BOM、`\n` 换行）

## 场景二：文件名单存在科学计数法

**现象**：sellerId 显示为 `2.21925E+12`，无法识别为有效 ID

**错误示例**：
```
2.21325E+12
2.21964E+12
```

**根因**：用户从 Excel 导出名单时，单元格格式是「数值」而非「文本」，长数字被自动转为科学计数法。

**解决方案**：
1. 在 Excel 中先把单元格格式改为「文本」
2. 重新粘贴 sellerId（不能直接粘贴数值，需粘贴为文本）
3. 复制到 TXT 文件
4. 或者直接告诉本 skill 原始 sellerId，让 skill 生成

## 场景三：单个 ID 数字后面有空格

**现象**：上传后报"格式错误"

**错误示例**：
```
2219635657158 
2213249110271
```
（第一行末尾有看不见的空格）

**解决方案**：本 skill 生成时自动 `strip()`，无需用户处理。手动处理时可用：
```bash
sed -i '' 's/[[:space:]]*$//' 打标.txt
```

## 场景四：每个 ID 后面有逗号

**现象**：上传后部分 ID 不识别

**错误示例**：
```
2213249110271,
2219635657158,
```

**根因**：用户从 SQL `IN (...)` 子句或 JSON 数组复制时带了逗号。

**解决方案**：
- 本 skill 自动 `rstrip(',;.')` 处理
- 手动处理：
```bash
sed -i '' 's/,$//' 打标.txt
```

## 场景五：文档中有非数字信息

**现象**：上传报"包含非法字符"

**错误示例**：
```
2219635657158 // 测试账号A
商家名: 2213249110271
2219635657158（备用号）
```

**解决方案**：本 skill 用正则 `^\d{10,16}$` 严格校验，不匹配则提示用户修正后重新提交。

## 通用排查清单

如果上传依然报错，按顺序检查：

```bash
# 1. 文件大小（不能为 0）
ls -la 打标.txt

# 2. 文件类型（应为 ASCII text）
file 打标.txt

# 3. 编码（不能有 BOM）
hexdump -C 打标.txt | head -1

# 4. 行尾（不能有 \r 或空格）
cat -A 打标.txt | head -5

# 5. 内容（每行纯数字）
grep -nE '[^0-9]' 打标.txt
```

任何一项不通过，重新生成文件后再上传。
