# 原创保护-维权规则详解

跨 6 个平台的维权链路。涉及侵权判定、申诉流程、平台对接差异。

## 6 平台清单

| 平台 | 接入方式 | 侵权识别 | 下架时效 |
|------|---------|---------|---------|
| 淘宝 | 内部接口 | 实时 | T+0 |
| 天猫 | 内部接口 | 实时 | T+0 |
| 拼多多 | API 对接 | 离线扫描 | T+1 |
| 抖音 | API 对接 | 离线扫描 | T+2 |

### 测试要点

- 6 个平台各自的下架成功率统计
- 平台 API 超时不应阻塞其他平台
- 失败重试规则（每平台不同）

## 侵权识别规则

### 自动识别（爬虫）

匹配维度：
- 商品标题相似度 ≥ 80%
- 主图相似度 ≥ 90%（图像哈希）
- SKU 属性匹配
- 价格区间（侵权品通常低于原价 50%）

### 人工识别

商家在维权工作台手动提交侵权链接：
- 必填：侵权链接、平台、侵权类型
- 选填：截图证据、文字说明

### 误报过滤

```
排除规则：
1. 关联商家自有店铺（同 main_shop_id）
2. 已授权的合作伙伴（白名单 yc_authorized_partner）
3. 历史申诉成功的链接（黑名单 + 解封时间）
4. 同主体多店铺（按 main_business_id 关联）
```

## 维权申请流程

```
检测到侵权（DETECTED）
  → 商家提交维权申请（APPLYING）
  → 调用各平台 API
  → 等待平台响应（TAKEDOWN_PENDING）
  → 下架成功（TAKEDOWN_SUCCESS） / 被申诉（APPEALED）
  → 申诉成功 → 重新上架 → CLOSED
  → 申诉失败 → 维持下架 → CLOSED
```

## 申诉机制

### 被投诉方申诉（侵权方）

```
被投诉方提交申诉
  → 维权状态变为 APPEALED
  → 商品保持在线
  → 平台审核 X 个工作日
  → 申诉成功 → 维权 CLOSED
  → 申诉失败 → 重新下架
```

### 商家二次申诉（被驳回的维权方）

仅淘宝/天猫支持，其他平台一次驳回不可申诉。

### 测试要点

- 申诉中商品状态：在线 / 离线？
- 申诉中是否计入下架率分母？
  - **答：分子分母都不计入**（参考结算规则）
- 申诉超时：自动判定失败
- 申诉证据上传：图片/文字/视频限制

## 维权能力上线/下线

### 绑定后上线

```
商品绑定专利（POST /api/bind）
  → MetaQ TOPIC_YC_BIND/bind
  → ProductBindConsumer
  → 写入 yc_right_product
  → 维权能力立即上线（爬虫开始监控）
```

### 解绑后下线

```
解绑（DELETE /api/bind）
  → MetaQ TOPIC_YC_BIND/unbind
  → ProductUnbindConsumer
  → 删除 yc_right_product
  → 维权能力立即下线（已生效的维权不撤销）
```

### 测试场景

| 场景 | 预期 |
|------|------|
| 绑定后立即检测侵权 | 应能检测到 |
| 解绑后已发起的维权 | 继续生效，不撤销 |
| 解绑后新的侵权 | 不再检测/不再发起维权 |
| 重新绑定 | 维权能力恢复 |

## 跨平台数据汇总

### 总下架率计算

```
total_takedown = SUM(各平台 takedown_count)
total_tort = SUM(各平台 tort_count)
overall_rate = total_takedown / total_tort
```

### 测试场景

| 淘宝 | 天猫 | 拼多多 | 抖音 | 小红书 | 京东 | 总下架率 |
|------|------|--------|------|--------|------|---------|
| 70/100 | 60/100 | 80/100 | 50/100 | 30/100 | 90/100 | 380/600 = 63.3% |

边界场景：
- 单个平台 100%，其他 0% → 总取决于权重
- 部分平台爬虫超时 → 该平台不计入分母

## 维权效果监控

### 关键指标

- **下架成功率**：takedown_success / total_apply
- **平均下架时长**：takedown_time - apply_time
- **申诉率**：appealed_count / takedown_count
- **申诉成功率**：appeal_success / appealed_count

### SQL 模板

```sql
-- 各平台下架成功率
SELECT platform, 
       COUNT(*) as total,
       SUM(CASE WHEN status='TAKEDOWN_SUCCESS' THEN 1 ELSE 0 END) as takedown,
       SUM(CASE WHEN status='TAKEDOWN_SUCCESS' THEN 1 ELSE 0 END) / COUNT(*) as rate
FROM yc_tort_record
WHERE gmt_create > DATE_SUB(NOW(), INTERVAL 30 DAY)
GROUP BY platform;
```
