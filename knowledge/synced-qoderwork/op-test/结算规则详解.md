# 原创保护-结算规则详解

资损敏感模块。所有规则均需 BigDecimal 精度，避免浮点误差。

## 核心计算公式

```
基础结算 = 500元 × SKU数
补贴 = 是否首发 ? 302元 : 202元（每个SKU）
官费 = 是否首发 ? 0 : 165元（每个SKU扣减）

最终拨付金额 = 基础结算 + 补贴 - 官费
            = 500×N + (302或202)×N - (0或165)×N
```

### 首发商品（每SKU）
```
500 + 302 - 0 = 802元/SKU
```

### 非首发商品（每SKU）
```
500 + 202 - 165 = 537元/SKU
```

## 触发条件（70% 下架率阈值）

```
下架率 = takedown_count / total_tort_count

触发结算条件：
  下架率 >= 0.7 AND total_tort_count >= 最小样本数
```

### 边界场景

| 下架数 | 总数 | 下架率 | 是否触发 |
|--------|------|--------|---------|
| 7 | 10 | 70.0% | 是 |
| 6 | 10 | 60.0% | 否 |
| 69 | 100 | 69.0% | 否 |
| 70 | 100 | 70.0% | 是 |
| 6999 | 10000 | 69.99% | 否 |
| 7000 | 10000 | 70.0% | 是 |

### 浮点精度陷阱

```python
# 错误：浮点比较
>>> 7/10 >= 0.7
True
>>> 0.7 == 7/10
True
>>> 6.999999/10 >= 0.7  # 实际计算可能误判
False  # 应该是 False
>>> 0.1 + 0.2 == 0.3
False  # ⚠️ 浮点精度

# 正确：BigDecimal
from decimal import Decimal, getcontext
getcontext().prec = 10
ratio = Decimal(takedown_count) / Decimal(total_count)
threshold = Decimal('0.7')
should_trigger = ratio >= threshold
```

## 6 个平台覆盖率

跨平台维权后，下架率合并计算：

```
总下架率 = SUM(所有平台下架数) / SUM(所有平台总维权数)
```

平台清单：
1. 淘宝
2. 天猫
3. 拼多多
4. 抖音
5. 小红书
6. 京东

### 测试要点

- 单平台 100% 下架，但其他平台 0% → 总下架率取决于权重
- 部分平台爬虫超时 → 该平台数据不计入总分母（避免拖累）
- 6 个平台分别验证下架成功后的 yc_tort_record 状态变化

## 多 SKU 结算

### 批量绑定 SKU 后部分被下架

| 场景 | 结算金额 |
|------|---------|
| 绑定 50 SKU，全部上架，触发下架 35 个 | 35 × 802（首发）或 35 × 537（非首发） |
| 绑定 50 SKU，绑定后下架 10 个，达成阈值时仅 40 SKU | 按 40 SKU 算（已下架的不计入） |
| 绑定 50 SKU，部分 SKU 申诉中 | 申诉中的不计入下架数（分母不变，分子不变） |

### SKU 状态变化时机

```
绑定时 SKU 数 N1
触发结算时 SKU 数 N2（N2 <= N1，已下架/已退款的不计）
拨付时再次校验 SKU 数 N3（防止 N2 → N3 期间 SKU 被下架）
```

最终金额按 N3（拨付时实际生效 SKU 数）。

## 重复结算防护

### 唯一索引设计
```sql
UNIQUE KEY uk_right_id (right_id)  -- 一个权利只能产生一个结算单
```

或：
```sql
UNIQUE KEY uk_right_stage (right_id, stage_no)  -- 阶段性结算
```

### 幂等保证
- SettlementCalcJob 重跑应被拒绝
- MetaQ 重复消费应被拒绝
- 测试方法：手动重复触发，验证 yc_right_settle_order 仅有 1 条

## 拨付链路

```
小二审核通过（status=APPROVED）
  → MetaQ TOPIC_YC_SETTLE/approval
  → SettlementApprovalConsumer
  → 调用 ERP 拨付接口
  → 等待 ERP 回调
  → MetaQ TOPIC_YC_SETTLE/payment
  → SettlementPaymentConsumer
  → status=PAID（终态）
```

### 失败回滚
- ERP 拨付失败 → status 仍为 APPROVED，等待重试
- 重试 3 次仍失败 → 进入死信，小二端告警
- 超过 7 天未拨付 → 自动告警 + 提单

## 测试场景模板（pytest）

```python
import pytest
from decimal import Decimal
from hsf_tool import setup_right, setup_tort_records, trigger_settlement

@pytest.mark.parametrize("sku_count, is_first_launch, takedown_count, expected_amount", [
    (1, True, 1, Decimal('802')),    # 1 SKU 首发，全下架
    (10, True, 7, Decimal('5614')),  # 10 SKU 首发，70% 下架率
    (10, False, 7, Decimal('3759')), # 10 SKU 非首发，70% 下架率
    (100, True, 69, None),           # 69% 不触发结算
    (100, True, 70, Decimal('56140')), # 100 SKU 首发，70% 下架率
])
def test_settlement_calculation(sku_count, is_first_launch, takedown_count, expected_amount):
    right_id = setup_right(sku_count=sku_count, is_first_launch=is_first_launch)
    setup_tort_records(right_id=right_id, total=sku_count, takedown=takedown_count)
    
    result = trigger_settlement(right_id)
    
    if expected_amount is None:
        assert result.triggered is False
    else:
        assert result.triggered is True
        assert result.amount == expected_amount
```

## 资金链路（doc4 实际业务规则）

### 完整资金流

```
正向: 商家订购付款500元 → 服务市场中间账户 → 淘宝服饰平台确收(首次退款后自动确收) → 到期结算服务商(按月)
逆向:
  未使用: 随时退款 → 服务市场垫资实时退款 → 淘宝平台月结补回服务市场
  已使用: 商家无法主动触发，根据业务规则系统结算
```

### 补贴回流机制

```
商品首次上架T+4 / 商品确认一致性T+4（取早）
  → 获取商品标签【首发】/【非首发】
  → 首发: 退回商家302元, 平台确收198元
  → 非首发: 退回商家202元, 平台确收298元
  → 获取标签失败: 延期至T+1重试直到服务期满
```

### 到期结算分支（保护服务到期日T+1判断）

| 下架率 | 供应商结算 | 商家退款 |
|--------|-----------|---------|
| ≥70% 或未发起维权 | **人工结算**: 500-165=335元/次 | 0 |
| <70% | **系统结算**: 0 | 退(335-302/335-202)即33或133元(扣除官费) |

### 退款策略

- **退款后自动确收剩余金额**
- 退款金额 = 剩余服务次数 × 500（**必须为全部剩余金额，不可部分退款**）
- 补贴退款原因: "满足平台限时限量服务补贴条件，根据首发规则发放补贴"
- 合作到期退款原因: "服务履约不满足承诺条件，除官费外服务费全额退款"
- 售后退款路径: 服务市场垫资退回商家 → 服务市场下月批扣服饰主体支付宝

### 开票规则

- 服务到期后允许商家开票
- 商家支付后冻结账单不允许开票，待期满解冻
- 下架率达成: 服务费133元(非首发)或33元(首发) + 官费165元
- 下架率未达成: 仅官费165元
- 链路: 国知局→服务商→淘宝→商家

## 12 个关键规则陷阱

1. **70% 浮点精度**：使用 BigDecimal 而非 float
2. **首发判断错位**：first_launch_status 字段未正确读取
3. **官费扣减规则**：首发不扣 165，非首发扣
4. **SKU 状态过滤**：已下架 SKU 不计入分母
5. **跨平台合并**：6 平台数据合并而非取最大
6. **重复结算**：唯一索引 + 幂等校验
7. **拨付时金额复算**：N1 → N2 → N3 三次校验
8. **申诉中 SKU**：分子分母都不计入
9. **超期结算**：7 天未拨付告警
10. **退款必须全量**: 退款金额必须等于订单剩余全部金额，不可部分退
11. **补贴前驳回退权益不退钱**: 补贴前终止退权益+1无退款; 补贴后终止退款不退权益
12. **必须先设补贴时间再设到期时间**: 否则补贴不发(HSF造数时注意顺序)
