# F88 疲劳度与频控（Tair计数器+时间窗口）

## Tair 计数器机制

### 模板匹配疲劳度

模板匹配处理器 `TemplateMatchProcessor` 中使用 Tair 计数器控制疲劳度：

- **计数粒度**：每模板每批次
- **最大次数**：5 次
- **原子性保证**：分布式锁
- **锁超时风险**：可能导致计数偏差

### 调度器防重标记

`Workflow2RecordStartJob`（核心调度器）使用 Tair 标记防止重复执行：

- 遍历所有租户，调用 `startSomeRecord(tenantId, 100)` 批量启动 INIT record
- 排除 APPROVE 节点（单独处理）
- Tair 标记防重，避免同一批次被多次调度

## 时间窗口控制

### 批次进度统计

`WorkflowBatchProgressJob` 定时扫描近期修改的批次，调用 `statisticProgress()` 更新进度统计。

### 审核任务生成时序

```
1. trigger_approve 打标（onNodeStart 时 toSubmit 等待）
2. ApproveTaskGenProgressJob 定时扫描
3. tryPushApproveTask() 生成审核任务
```

**QA 风险点**：approve 节点需先 trigger_approve 打标，再 try_push_approve_task 生成任务，两步顺序关系。

## 限流控制

### 批量启动限流

- `startSomeRecord()` 每次限流 count=100
- 跨所有 PROCESSING 批次批量启动 INIT record
- 通过 SchedulerX 定时触发，控制水位

### 模型 QPS 限制

通过 Diamond 动态配置（`GeminiModelConfig`）设置每模型 QPS 上限。

## 状态流转与频控关系

**节点状态流转**：`INIT → TO_SUBMIT → HANDLING → SUCCESS / FAIL`（审核节点额外有 `RETRYING`、`PERM_FAIL`）

**批次状态**：`INIT → SUBMITTED → PROCESSING → FINISHED / TERMINATED`

- `OVER_STATUS_LIST` = SUCCESS + FAIL + PERM_FAIL
- `HANDLING_STATUS_LIST` = HANDLING + RETRYING
