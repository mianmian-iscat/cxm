# 测试用例设计方法论

## 功能测试用例设计方法

### 等价类划分
- 有效等价类：合理输入，系统应正常处理
- 无效等价类：不合理输入，系统应给出错误提示
- 每个等价类至少选取一个代表值

### 边界值分析
- 针对数值型：最小值、最小值+1、最大值-1、最大值、超出范围值
- 针对字符串：空串、单字符、最大长度、超长、特殊字符
- 针对日期：月初/月末、闰年、跨年、时区差异
- 针对列表：空列表、单元素、满容量

### 状态迁移测试
- 绘制状态迁移图
- 覆盖所有合法状态转换路径
- 验证非法状态转换被拒绝
- 关注并发状态冲突

### 错误猜测法
基于经验的常见错误场景：
- 网络中断/超时/重复提交
- 并发操作同一资源
- 大数据量下的性能退化
- 权限越级访问
- 缓存与数据库不一致
- 消息队列消费失败重试

## F88/i-FASHION 项目特有测试维度

### 审核流程测试
- 审核状态流转（待审核→审核中→已通过/已驳回/已丢弃）
- 重新审核触发条件
- 审核Prompt字符限制（2000字符）
- 图片上传格式限制（png/jpg/jpeg）
- 已丢弃状态支持重新审核

### 抽检功能测试
- 抽检任务创建与分配
- 抽检通过率（passRate）与正确率（accuracyRate）独立计算
- 抽检状态：1=已完成, 2=待抽检, 0=重置后待审核
- 视频抽检驳回弹窗（测试原因1/2/手动输入）
- consistency字段对accuracyRate的影响

### 策略平台测试
- 批次生命周期管理
- 各环节（设计改款/视觉生图/视觉审核/算法过滤/套图生产/选款推送）状态检查
- 节点重试与失败恢复
- LLM资源监控

### 数据一致性测试
- workflow_record_log 与 g_workflow_instance 表数据一致性
- JSON字段（common_variable/extra_info）提取准确性
- 分区表（ds字段）数据产出时效性

## 用例优先级定义

| 优先级 | 定义 | 示例 |
|--------|------|------|
| P0 | 阻塞性/核心流程，必须通过 | 核心业务流程、数据丢失、系统崩溃 |
| P1 | 重要功能，影响主要使用 | 非核心但常用功能、数据不一致 |
| P2 | 一般功能，有替代方案 | 辅助功能、UI展示异常 |
| P3 | 低优先级，体验优化 | 文案错误、样式微调 |
