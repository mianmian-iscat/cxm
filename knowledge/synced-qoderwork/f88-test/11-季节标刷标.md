# F88 季节标刷标（SeasonTag2Processor）

## 概述

季节标（`season_tag`）是素材生产链路"刷标签"环节的核心节点，由 `SeasonTag2Processor` 处理。
需求 83728544 新增了兜底逻辑：当 `compositionNames` 中无季节关键词时，默认赋值"春"，
避免之前 `seasonTagName` 为空导致 `FAIL`+"季节标未识别"的问题。

**核心规则：任何涉及"走链路"的测试，必须包含本文底部的 18 条回归用例。**

## 处理器详情

| 属性 | 值 |
|------|-----|
| NodeType | `season_tag` |
| 处理器类 | `SeasonTag2Processor` |
| 支持重试 | ✅ |
| 所在环节 | 刷标签（stageId=`8fec0929`，strategyName=`【zy测试】入参图刷标签`） |

### 核心业务逻辑

```
buildFinishMessage():
  1. 从模型返回的 compositionNames 中提取季节标
  2. parseSeasonTag(compositionNames):
     - 遍历 compositionNames 列表
     - 对每个元素调用 SeasonTagEnum.fromDesc(name)
     - fromDesc() 是精确匹配（"春"→春, "夏"→夏, "秋"→秋, "冬"→冬）
     - first-match-wins：首个非null立即返回
  3. 如果 parseSeasonTag 返回 null（所有 compositionNames 都未匹配到季节词）：
     - 【兜底】seasonTagName = "春"（fallbackSeasonTags 默认值）
  4. season_tag 写入 output_json.season_tag
  5. compositionNames 回填到 output_json.composition_tag（不管有没有兜底都回填）
```

### 关键枚举

`SeasonTagEnum`：仅接受 `春/夏/秋/冬` 四个精确值，`fromDesc()` 不做模糊匹配。

### 输入输出

| 方向 | 字段 | 说明 |
|------|------|------|
| input | `imgUrl` | 种子图 URL |
| output | `season_tag` | 识别/兜底后的季节标（春/夏/秋/冬） |
| output | `composition_tag` | 原始 compositionNames 列表（30+项） |
| output | `outputImgUrl` | 输出图 URL |

### 下游传递

season_tag 写入 `g_workflow_instance.common_variable.season_tag`，被下游 strategy 节点（入参图刷标签）消费。
下游策略（首图生图）通过 `common_variable` 读取 `season_tag` 进行模板匹配（SEASON 维度）。

## DMS 查询约束

`workflow_record_log` 是超大表，查询必须遵守以下规则：

```sql
-- ✅ 正确：用 batch_id IN 走索引
SELECT * FROM workflow_record_log
WHERE batch_id IN ('BT_5970','BT_5971','BT_5972','BT_5973')
AND node_type = 'season_tag';

-- ❌ 错误：无 batch_id 全表扫描必超时（DMS 20s限制）
SELECT * FROM workflow_record_log
WHERE node_type = 'season_tag' AND gmt_create > DATE_SUB(NOW(), INTERVAL 7 DAY);
```

**只有 `batch_id` 有索引**，`node_type`/`gmt_create`/`status` 均无索引。
跨批次查询用 `batch_id IN (...)` 拼接，不要用时间范围替代。
