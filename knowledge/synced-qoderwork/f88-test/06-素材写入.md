# F88 素材写入（信息流发布+路由+幂等）

## 裂变（Fission）逻辑

当上游节点是 `GenImgNode` / `MapGenImgNode` / `FabricTryOnNode` 且 `outputModel = SINGLE` 时，每张输出图片独立创建下游 record，路径跟踪格式如 "1.1"、"1.2"、"1.3"。

**QA 风险点**：裂变后 record 数量可能远超输入行数（1 张图 → N 条 record），进度统计需按裂变后总数计算。

## 审核节点处理器（`ApproveProcessor`）

审核节点是生产与审核系统的桥梁：

```
1. onNodeStart() 时不立即执行，调 toSubmit() 等待
2. ApproveTaskGenProgressJob 定时扫描 → approveAppService.tryPushApproveTask()
3. createApproveJob() 收集所有 TO_SUBMIT record → 构建 ReviewTaskCreateCmd
4. 创建主任务（MAIN_TASK）+ 子任务（每条 record 一个）
5. relationId = batchId_nodeId_minLogId（幂等键）
6. 审核完成 → ReviewMainTaskFinishMessage → ReviewSubTaskFinishMessage
7. → WorkflowRecordFinishMessage（含 pass/notPass + 原因）
8. notPass=true → 引擎终止该 record 流程（terminated=true），创建策略 error record
```

**审核类型**（`ApproveTypeEnum` / `ApprovalTypeEnum`）：

| 类型 | 名称 | 审核内容 VO |
|------|------|-------------|
| 2 | 套图审核 | `MultiImageAuditContentVO`（审核人选择最佳图） |
| 3 | 视频审核 | `VideoAuditContentVO` |

> ⚠️ 类型 1（单图审核）已下线，不再存在。

## AI 生图处理器（素材创建）

| NodeType | 处理器 | 处理类型 | 核心逻辑 |
|----------|--------|----------|----------|
| `gen_img` | `GenImgProcessor` | AI 生图 | 图片生成（继承 `GenAbstractProcessor`），`TaskSceneEnum.GEN_IMG`，成功后创建素材 |
| `map_gen_img` | `GenImgMapProcessor` | AI 生图 | MAP 多图生成（多 prompt），类似 GenImg 但处理多 prompt |
| `fabric_tryon` | `FabricTryOnProcessor` | AI 生成 | 面料上身 |
| `crop_head` | `ImageCropProcessor` | 图片处理 | 人脸框检测 + 裁头 |

## 写入幂等保证

- `checkDataProcessed()` 幂等检查（防重复提交）
- 审核任务 `relationId = batchId_nodeId_minLogId`（幂等键）
- `WorkflowRecordFinishMessage` 确保状态一致性

**QA 风险点**：
- 回调丢失会导致 record 卡在 HANDLING（已知问题：AfdJob `job_status` 回调不可靠，88% 的 job 卡在 INIT 未更新）
- `checkDataProcessed()` 幂等检查可能误判导致跳过合法任务
