# 铁律 2: 测试必须串联多 Skill 验证

> **级别**: 行为规范 | **违反后果**: 验证不完整，遗漏后端问题

## 规则

测试流程中必须串联多个 Skill 形成完整验证链路，禁止只用单一工具做单层验证。

## 标准验证链路

```
1. UI 验证（browser-use / playwright MCP）
   ↓ 确认页面表现符合预期
2. DB 验证（dms-alibaba-cli）
   ↓ 确认数据真正持久化或未被篡改
3. 日志检查（aliyun-sls-log-query）
   ↓ 排查后端异常、接口报错
4. 缺陷提交（aone-bug-submit）— 发现 bug 时
   ↓ 直接提交 Aone
5. 结果通知（dws 钉钉）— 测试完成时
   ↓ 推送结果到群
```

## 检查清单

每轮测试结束后，检查是否需要补充：

- [ ] DB 层验证：数据是否落库？字段值是否正确？
- [ ] 日志层验证：后端是否有异常日志？接口是否报错？
- [ ] 缺陷提交：发现的 bug 是否已提交？

## 禁止行为

- 只做 UI 验证就收工
- 跳过 DB 层验证（数据可能没落库）
- 跳过日志检查（后端可能报错但前端没体现）
