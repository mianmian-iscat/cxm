# 原创保护平台 - 测试知识库

沉淀业务规则、已知问题、测试要点和踩坑记录，供测试用例设计时参考。

## 全局测试约定

### 测试数据构造方式

- 一律走接口（MTOP/API），不走 UI 手动操作
- 商家端使用 `window.lib.mtop.request()` 调用 MTOP API（需浏览器内执行，预发 SSO 是 httpOnly cookie）
- 小二端使用 `fetch('/mtop/...')` 调用 cobweb API
- 充值等无直接 API 的场景走半自动方式（UI 建单 + API 取支付链接），不全程走 UI
- **原因**：接口方式可复现、可脚本化、避免 UI 变更导致的自动化脚本失效

## 二、专利申请

### 2.1 快审 (QUICK)

- 仅需: 商品图片(主视图必填, 其他可选) + 预计上架日期
- 提交→YC机构→当天(工作日)出结果
- 通过→状态"快审通过(待补充信息)"→"去补充"填完整申请→进入初审
- 驳回→显示驳回原因+附件下载+审核人信息，状态"专利申请已终止"
- 小二可发起快审(sellerId查商家+上传图片+日期)，仅小二发起的快审结果发钉钉通知

### 2.2 初审 (PRE)

- 完整字段: 设计师(姓名/身份证/国籍/手机/证件照)、联系人、商品名/类目/用途、设计要素、6角度图
- 提交→YC机构初审(通过/驳回/补正)
- **补正**: 支持查看/下载附件; 格式: jpg/png, pdf/doc/docx/xls/xlsx, zip/rar/7z/tar/gz
- 初审补正通过→生成带电子签章的承诺书PDF(OSS存储)
- 驳回→退1次权益+可转普通申请

### 2.3 普通申请 (REGULAR)

- **来源**: 快审/初审驳回后商家选择"转普通申请"
- **流程**: 驳回退1次权益→展示建议理由→二次确认(提示无补贴、扣权益)→扣1次权益→提交YC
- 普通申请周期~8-10月，无平台补贴
- 超时(检索报告有效期~3天)不操作→自动更新"专利已申请驳回"
- 小二后台首发字段显示"-"

#### 2.3.1 专利驳回转普通申请 [需求#83163231]

**触发条件**: 初审驳回(PRE_PRE_AUDIT_REJECT)、预审驳回(PRE_AUDIT_REJECT)、认证驳回(CERT_REJECT) 触发转普通建议。快审驳回(QUICK_REJECT)不触发。

**流程**:
1. 驳回后后端写入 `to_regular_status=TO_DO` + `to_regular_suggest_time`
2. 商家端详情页初审驳回节点显示"提交普通申请"按钮（仅TO_DO状态可见）
3. 按钮 hover 显示 Tooltip（国知局受理说明）
4. 点击按钮弹出 `Modal.confirm` 二次确认
5. 确认后调用 submitToRegular API → `toRegularStatus` 变为 DONE
6. 3天内未操作 → 定时任务自动将 TO_DO 更新为 TIMEOUT

**API 新增字段**: `bzb.api.sceneplatform.tbyc.right.apply.get` 返回 `toRegularStatus`/`suggestToRegularReason`/`regularApply`

**前端组件**: `StatusTimeline/index.tsx` (industry-source-code/original-protection)

**测试要点**:
- 按钮仅在 `toRegularStatus=TO_DO` 时展示
- Tooltip 文案与 PRD 逐字对比
- `Modal.confirm` 文案与 PRD 逐字对比（注意"暂不享受"vs"将不享受"）
- TIMEOUT 超时机制（suggest_time + 3天）
- `to_regular_status` 非空时首发字段不可编辑

### 2.4 草稿功能

- 申请页"保存草稿"按钮; 草稿不消耗权益
- 列表新增"草稿"Tab(蓝色标签)
- 草稿→正式提交时走完整校验

### 2.5 取消申请

- 初审通过前: 商家可自行取消(退权益+1)
- 初审通过后: 仅YC可取消
- 快维/国知局阶段: 仅YC可取消
- 已终止/已驳回/已发证: 不可取消

### 2.6 快审服务次数扣减时机 [需求#83368125, 2026-06-24]

- **扣减节点变更**: 旧代码在快审提交时扣减，新代码改为初审提交(SUBMIT_APPLY)时扣减
- **扣减机制**: 通过 `yc_right_settle_order` 结算单实现，非 `yc_service_trade_record`
- **结算单生命周期**: TO_DO → DONE（后台定时任务处理，约50分钟）
- `remainRightCount` 由服务市场侧计算，非YC平台直接计算
- **快审全程不扣减**: 发起/通过/驳回均无结算单、无交易记录、count不变
- **快审驳回不返还**: 新代码快审未扣减，驳回时无结算单，无需返还（旧代码驳回时settle CANCEL返还）
- **商家端快审无次数校验**: 新代码移除快审的服务次数校验，`remainRightCount=0`仍可提交快审
- **真实快审审核限制**: HSF `TopRightHsfService.syncAuditOperation` 为模拟调用，仅记录op_record不推进状态；真实通过/驳回须钉钉@卢彩xq（专利机构lzxc）操作
- **存量数据**: 旧代码驳回的申请（如200000731 settle 416 CANCEL）无需处理

### 测试要点（快审扣减专项）

- 快审发起后查settle_order无新增、trade_record无新增、remainRightCount不变
- 快审通过（HSF模拟或真实）后查settle_order无新增
- 快审驳回后查settle_order无新增、remainRightCount不变
- 初审提交后查settle_order新增（status=TO_DO），约50min后变为DONE
- 新旧代码驳回行为对比：旧代码settle CANCEL，新代码无settle
- 商家端count=0发起快审仍成功（无次数校验）
- cobweb API因CSRF限制fetch失败，需改用UI自动化

### 测试要点

- 快审Tab/初审Tab切换字段可见性
- 快审当天出结果(工作日)
- 快审通过→"去补充"预填商品图和日期
- 补充材料各格式上传校验(大小/类型)
- 驳回→权益+1→转普通→权益-1的完整流程
- 3天超时自动状态更新
- 草稿CRUD+不消耗权益
- 取消申请各阶段的权限控制
- YC取消: 各阶段退权益+1

## 四、维权保护

### 业务规则

- **巡检机制**: 前3个月自动巡检(第1月周频, 之后双周); 3个月后商家手动
- **手动线索**: 店铺名+平台+商品URL(自动解析标题/图片)+店铺链接
- 支持平台: 淘宝/天猫/抖音/小红书/拼多多/京东
- **维权状态**: 维权成功(已下架) / 维权中 / 维权失败 / 暂未构成侵权
- 到期前20天维权按钮禁用
- 70%下架率为服务承诺阈值
- **去除绿网校验**: 添加线索/白名单不再调用内容审核API

### 测试要点

- 自动巡检→手动线索的流程切换
- URL自动解析商品信息(`parseItemInfoByUrl`)
- 跨6平台的维权发起流程
- "暂未构成侵权"状态(YC判定线索不构成侵权)
- 维权失败→可走律所群诉讼
- 到期前20天禁维权(按钮灰+文案)

## 五、专利回转与到期

### 业务规则

- **回转窗口**: 商品一致性确认后180天 ~ 国知局申请日+11个月
- **放弃专利**: 二次确认→状态"专利保护已失效"→显示"原创保护到期，已放弃专利"
- **申请专利转回**: e签宝电子签署→二次确认
- **转让目标**: 本人/本店铺主体/其他(自由文本100字)
- **必须签署**: 转让协议、专利代理委托书
- 目标为"其他"时额外签署: 专利转让确认书
- **状态**: "原创保护到期，专利回转中"→"专利已回转"
- 超时未操作=自动放弃
- **到期日计算**: `min(一致性确认+180天, 国知局提交+1自然年-30天)`, Diamond可配

### 测试要点

- 回转窗口开始/结束时间计算(含Diamond配置覆盖)
- e签宝三方文档签署流程(转让协议/委托书/确认书)
- 不同转让目标的文档差异
- 超时自动放弃
- 到期日两种计算方式取最小值

## 六、首发标签与打标

### 业务规则

**"是否首发"编辑规则**:

**前置条件（两个必须同时满足，缺一不可）**：
1. 商家主营类目在9类白名单中（取 SYNC_CERT_FILE 时刻的 ODPS 快照）
2. 该申请未走过转普通流程（`to_regular_status ≠ DONE`）

> **[校准 2026-06-30]** 不满足前置条件时，两端（商家端+运营端）均不可编辑首发（disabled灰态无tooltip）。非9类商家即使未转普通也不可编辑；9类商家已转普通后也不可编辑

**5种时间组合（满足前置条件后）**:
1. 首次上架时间空 + 一致性确认时间空 → 不可编辑
2. 首次上架有 + 确认时间空 → 不可编辑
3. 首次上架空 + 确认时间有 → 以确认时间为基准
4. 两者都有 → 取较早时间为基准
5. 基准时间T+3天内: 可编辑; T+4天0:00后: 从未编辑过的可编辑一次; 已编辑过的锁定

- 一致性确认后标签不可变
- 店铺URL自动入白名单: 签约时`shopId`格式 `https://shop{shopId}.taobao.com`
- 小二后台首发编辑: 3天窗口+tooltip截止时间; 商品在仓库不可确认; 一致性失败清空标签

### 测试要点

- 5种时间组合全覆盖
- T+3/T+4边界精确到0:00
- 已编辑vs未编辑的T+4行为差异
- 店铺URL格式和自动入白名单
- 历史数据初始化
- 一致性失败→清空→重新绑定→恢复

## 七、结算系统

### 状态机

```
进行中 → 首发打标前 → 打标后 → 补贴中 → 已补贴
  ↓ (分叉)
完结待退款 / 完结无需退款 → 完结退款中 → 完结已退款/待确收 → 已确收
已取消(预补贴驳回/终止)
```

### 结算规则

- 500元/SKU, 官费165元(申请75+年费90)
- **补贴**: 首发302元/非首发202元(T+4退还商家, 从服务市场托管退)
- **到期下架率>=70%**: 付供应商335元
- **到期下架率<70%**: 退商家(500-补贴-官费=500-302-165=33元(首发) 或 500-202-165=133元(非首发))
- 退款金额=剩余次数×500(必须等于全部剩余, 不可部分退)
- 驳回/终止: 补贴前退权益+1; 补贴后退款不退权益
- 发票冻结/解冻: ODPS月洗, 进行中→冻结, 已完成→解冻
- 并发锁: 提交时按商家加锁, 选取未关联结算的订阅单(余额500)

### HSF测试工具

- `RightSettleToolHsfService::getSettleOrderByApplyId` — 按申请ID查结算单
- `RightSettleToolHsfService::updateInitAllowanceStartTimeWithApplyId` — 改补贴起始时间
- `RightApplyToolHsfService::updateApplyTime` — 改申请时间
- `RightApplyToolHsfService::updateProtectExpiredTime` — 改到期时间
- `ServiceTradeToolService::triggerRefund` — 触发退款

### 测试要点

- 补贴金额: 首发302 vs 非首发202(测试环境0.06/0.04)
- T+4补贴触发时机
- 到期退款计算(下架率>=70% vs <70%)
- 退款金额=剩余×500(部分退不允许)
- 补贴前驳回→退权益+1(无退款)
- 补贴后驳回→退款(不退权益)
- 并发锁: 同时提交两个申请
- 定时任务触发条件匹配

### 踩坑记录

- **必须先设补贴时间再设到期时间**, 否则补贴不发
- 无首发标签→无补贴
- 订单反转(退款后)补贴不再发放
- 服务到期前无首发标签→无补贴

## 十三、童装童鞋业务扩展（需求#83078557）

### 核心规则

- 新增童装/童鞋等业务，但补贴资格仅限9个指定一级类目
- **9类eligible类目ID**: 女装(16), 男装(30), 女鞋(50006843), 流行男鞋(50011740), 内衣(1625), 服饰配件(50010404), 箱包(50006842), 眼镜(28), 手表(50468001)
- 童装/童鞋没有独立的一级类目ID，正向测试只看上述9个类目值
- 非9类商家的判断逻辑: 主营类目ID不在上述9类集合中
- **数据源**: `cco_busi.dplan_dim_tb_slr_mx_d_1` 取主营类目(主类目)

### 非9类商家行为差异

- **签约/入驻**: 正常，不受类目限制
- **专利申请(快审/初审/普通)**: 正常，流程与9类一致
- **商品绑定/维权**: 正常，无特殊限制
- **补贴**: 不发放（判断依据: `init_allowance_start_time IS NULL`，非 `total_amount`）
  - > **[校准 2026-06-30]** `total_amount` 是基础结算金额，非9类商家也有值（测试环境=10，生产=50000），不因补贴逻辑改变。补贴是否发放看 `init_allowance_start_time` 是否被赋值。当 `init_allowance_start_time IS NOT NULL` 时，`init_allowance_amount` 才有值（首发=6，非首发=4，测试环境）
- **运营后台"是否首发"**: 不可编辑，直接disabled不可点击（无tooltip文案）
- **退款**: 到期退款=500×剩余次数（全额退，不扣补贴和官费）

### 已确认的业务规则

- > **[校准 2026-06-30]** 商家签约后可以变更主营类目（实测 seller 2213249110271 从 124484008 变更为 50010404）。补贴校验取 SYNC_CERT_FILE 时刻的 ODPS 主营类目快照，商家后续变更主营不影响已确认的申请（历史申请按确认时的类目判定）。需作为边界用例覆盖：同一商家跨越主营变更前后，补贴结果不同的场景
- 非9类商家首发列不可编辑时，没有tooltip提示，UI直接灰态不可交互
- 后端API(`setRightFirstPublish`)应对非9类商家的请求返回错误

### 测试要点

- 9类商家的回归测试不受影响
- 非9类商家全流程可走通(除补贴和首发编辑)
- 类目ID精确匹配(非前缀匹配)
- > **[校准 2026-06-30]** `total_amount` 是基础结算金额，非9类商家也有值，不可与补贴金额混用。断言补贴应看 `init_allowance_start_time`，不看 `total_amount`

**自动执行 6 步流程**：
1. 场景识别（30秒内）：提取测试目标、涉及的表、API、规则域
2. 环境准备：打开预发页面、确认测试账号、检查山海关开关
3. 数据准备：检查是否需要造数（HSF Tool）
4. API断言：浏览器内执行 MTOP 调用，捕获响应
5. DB校验：执行 SQL 查询，比对预期值
6. UI验证：检查页面组件状态
7. 结果判定：自动判定 PASS / FAIL / BLOCKED

**场景路由示例**：
- “结算” → 结算金额计算校验流程
- “补贴” → 补贴触发条件验证

### 14.4 阻塞处理三层策略
