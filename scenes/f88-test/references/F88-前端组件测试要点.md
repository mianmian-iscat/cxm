## 1. React 受控输入框（Input）

### 问题
F88 所有 `<input>` 均为 React 受控组件，普通 `fill` 无法触发 state 更新。

### 解法
```json
{
  "action": "fill",
  "selector": "input[placeholder='请输入']",
  "value": "测试",
  "react": true
}
```

**原理**：`react: true` 使用 native setter + dispatchEvent 模式：
```javascript
const nativeInputValueSetter = Object.getOwnPropertyDescriptor(
  window.HTMLInputElement.prototype, 'value'
).set;
nativeInputValueSetter.call(element, '测试');
element.dispatchEvent(new Event('input', { bubbles: true }));
element.dispatchEvent(new Event('change', { bubbles: true }));
```

### 坑点
- 两个搜索框共用同一 selector `input[placeholder='请输入']`
- 用 `selectorIndex: 0` 表示商家名称，`selectorIndex: 1` 表示商家ID
- 清空输入框：先 `fill` 空字符串，再 dispatch change

## 2. Ant Design Select 下拉选择器

### 标准操作流程
```
1. 点击 .ant-select 触发下拉展开
2. 等待 .ant-select-dropdown 出现（动画 200ms）
3. 在 dropdown 中点击目标 .ant-select-item-option
4. 等待 dropdown 消失
```

### 试运行弹窗中的“运行类型”下拉
```json
{
  "action": "click",
  "selector": ".ant-select",
  "note": "必须用 page.mouse.click() 展开，evaluate().click() 无效"
}
```

**重要**：策略平台的 Select 组件必须用鼠标物理点击，`evaluate` 方式触发的 click 不会展开下拉面板。

### 🚨 实战经验（来自 Qoder 会话）

**链路20180试运行问题复现过程**：
1. 首次执行发现运行类型未选中——截图确认弹窗已出现但 Select 未展开
2. 尝试 placeholder 点击 + keyboard 模拟均失败
3. 定位到 Ant Design Select 渲染特性：**下拉菜单挂载在 body 末尾**，不在弹窗 DOM 内
4. 解法：点击 `.ant-select-arrow` 触发 → `evaluate` 检查 `.ant-select-dropdown:not(.ant-select-dropdown-hidden)` 状态
5. Fallback：若未展开，用 `mouse.click` 坐标触发 + 再次 evaluate 选择首个选项

**完整鲁棒性方案**：
```javascript
// Step 1: 精确点击展开
async function openSelect(page, selectSelector) {
  const arrow = await page.$(selectSelector + ' .ant-select-arrow');
  if (arrow) {
    await arrow.click();
  } else {
    // fallback: 坐标点击
    const box = await page.$(selectSelector).then(el => el.boundingBox());
    await page.mouse.click(box.x + box.width - 10, box.y + box.height / 2);
  }
  await page.waitForTimeout(300);
}

// Step 2: 确认展开状态
async function verifyDropdownOpen(page) {
  return await page.evaluate(() => {
    const dd = document.querySelector('.ant-select-dropdown:not(.ant-select-dropdown-hidden)');
    return dd !== null;
  });
}

// Step 3: 选择目标项
async function selectOption(page, optionText) {
  await page.evaluate((text) => {
    const options = document.querySelectorAll('.ant-select-item-option-content');
    for (const opt of options) {
      if (opt.textContent.trim().includes(text)) {
        opt.closest('.ant-select-item').click();
        return;
      }
    }
  }, optionText);
}
```

**关键教训**：规避 puppeteer-core 不支持 `$x` 的问题，改用 `document.querySelectorAll` + `evaluate` 实现元素查找。

### 多选 Select
- 已选项显示为 tag，需点击 tag 上的 × 删除
- 清空按钮：`.ant-select-clear`（hover 后出现）

## 3. Ant Design Drawer 抽屉组件

### 出现场景
- 审核详情：点击“审核”按钮，从右侧滑出

### 操作要点
```
1. 触发 Drawer 打开
2. 等待 .ant-drawer 出现
3. ⚠️ 动画时长约 300ms，必须 wait 500ms 后再操作内部元素
4. 操作完成后 Drawer 自动关闭（或点击遮罩层关闭）
```

### 🚨 实战经验：按钮DOM存在但不可见

**问题现象**：在 F88 审核详情页中，高清化/驳回/裁剪按钮虽然存在于 DOM（`img[alt=高清化/驳回/裁剪]`，class=`CoverImageReview--actionItem`），但父容器 `CoverImageReview--imageActions` 的 `display=none`，导致 `getBoundingClientRect` 返回 0×0，无法点击。

**正确验证逻辑**：
```javascript
async function isButtonClickable(page, selector) {
  return await page.evaluate((sel) => {
    const el = document.querySelector(sel);
    if (!el) return { exists: false };
    const rect = el.getBoundingClientRect();
    const style = window.getComputedStyle(el.parentElement);
    return {
      exists: true,
      visible: rect.width > 0 && rect.height > 0,
      parentDisplay: style.display,
      clickable: rect.width > 0 && style.display !== 'none'
    };
  }, selector);
}
```

**规则**：不能仅通过 DOM 搜索确认按钮“存在”就认为可交互，必须同时检查 `getBoundingClientRect` 的 width/height > 0 和 `computedStyle.display !== 'none'`。

### 常见错误
- 动画未完成时操作内部按钮 → 点击事件丢失
- Drawer 内的按钮可能初始为 disabled，需等待数据加载完成
- **按钮DOM存在但不可点击**（父容器 display:none）— 必须检查可见性

## 4. Ant Design Modal 弹窗

### 出现场景
- 审核确认弹窗
- 驳回原因填写弹窗
- 批量审核确认弹窗
- 试运行弹窗
- 新建链路/策略弹窗
- 查看运行结果弹窗

### 操作要点
```
1. 触发按钮点击
2. 等待 .ant-modal 出现 + .ant-modal-mask 出现
3. 弹窗内操作
4. 点击确认/取消
5. 等待 .ant-modal 消失
```

### 🚨 实战经验：tc27 端到端测试中的弹窗踩坑

**问题 1：策略新建是弹窗，非页面跳转**
- 初始脑本认为 "新建策略" 会跳转到新页面，实际是 Modal 弹窗
- 必须先检测 `.ant-modal` 是否出现，再进行表单填写

**问题 2：按钮文本含空格**
- 实际按钮文本为 "保 存"（含不间断空格）而非 "保存"
- 解法：使用正则匹配 `/保.*存/` 而非精确文本

**问题 3：确认按钮多文案**
- 不同弹窗的确认按钮文案不一致：“创建”“确定”“添加”“确认”
- 解法：匹配正则 `/确.*定|创建|添加|提交/`

**问题 4：弹窗未触发（依赖交互状态）**
- Ant Design 组件弹窗可能延迟渲染或依赖交互状态
- 解法：增加重试逻辑，不能仅依赖静态 DOM 查找

```javascript
// 弹窗确认按钮通用点击
async function clickModalConfirm(page) {
  const confirmTexts = [/确.*定/, /创建/, /添加/, /提交/, /保.*存/];
  await page.evaluate((patterns) => {
    const buttons = document.querySelectorAll('.ant-modal .ant-btn-primary');
    for (const btn of buttons) {
      const text = btn.textContent.replace(/\s/g, '');
      if (patterns.some(p => new RegExp(p).test(text))) {
        btn.click();
        return;
      }
    }
    // fallback: 点击最后一个 primary 按钮
    if (buttons.length > 0) buttons[buttons.length - 1].click();
  }, confirmTexts.map(r => r.source));
}
```

### 坑点
- Modal 内可能嵌套 Select 组件，dropdown 渲染在 `document.body` 而非 Modal 内
- Modal footer 按钮的确认/取消顺序：`[取消, 确认]`（确认通常在右侧）
- 某些 Modal 的确认按钮受表单验证控制，必填字段未填时 disabled
- **按钮文本可能含空格/特殊字符**，必须用正则匹配

  <div class="ant-table-header">...</div>
  <div class="ant-table-body">

## 10. 策略平台节点编排

### 新增节点弹窗
- 点击 "+ 新增节点" → 弹窗展示 20 种节点类型
- 节点类型为卡片布局或列表布局
- 选择节点类型后弹窗关闭，画布上新增节点

### 🚨 实战经验：节点卡片选择的鲁棒性实现

**问题**：节点卡片的标题+描述混排，精确文本匹配失败（如“生图”卡片实际文本为“生图文生图模型生成图片”）

**三重 Fallback 方案**：
```javascript
async function selectNodeType(page, nodeName) {
  const result = await page.evaluate((name) => {
    const cards = document.querySelectorAll('.ant-modal .ant-card, .ant-modal [class*="node"]');
    
    // 策略 1：精确匹配标题
    for (const card of cards) {
      const title = card.querySelector('[class*="title"], .ant-card-head-title');
      if (title && title.textContent.trim() === name) {
        card.click();
        return 'exact';
      }
    }
    
    // 策略 2：宽松包含匹配
    for (const card of cards) {
      if (card.textContent.includes(name)) {
        card.click();
        return 'contains';
      }
    }
    
    // 策略 3：坐标点击（按顺序取第N个卡片）
    return 'fallback_needed';
  }, nodeName);
  
  if (result === 'fallback_needed') {
    // 坐标点击目标位置
    const cards = await page.$$('.ant-modal .ant-card');
    if (cards.length > 0) {
      const box = await cards[0].boundingBox();
      await page.mouse.click(box.x + box.width/2, box.y + box.height/2);
    }
  }
}
```

### 节点连线
- 节点之间通过拖拽连线
- 连线操作需要精确坐标定位（起点/终点连接点）

### 坑点
- 节点编排区域可能使用 Canvas 或 SVG，非标准 DOM 元素
- 画布缩放/平移会影响坐标计算
- 连线失败不会有明确报错，需检查节点配置是否生效
- **节点卡片标题+描述混排**，不能用精确文本匹配

## 11. 通用最佳实践

| 实践 | 说明 |
|------|------|
| 操作前清水印 | `document.querySelectorAll('.wm_div_id').forEach(el => el.remove())` |
| React 输入用 native | 所有 input/textarea 统一 `react: true` |
| 等待动画完成 | Drawer 500ms, Modal 300ms, Select dropdown 200ms |
| 截图用 CDP | `Page.captureScreenshot`，不用 `html2canvas` |
| Select 用鼠标点击 | 策略平台 Select 不响应 programmatic click |
| 验证状态变化 | 操作后等待 API 响应 + DOM 更新 |
| 分页表格先滚动 | checkbox 可能在视口外 |
| 弹窗内 dropdown | 在 `document.body` 层级，不在 Modal 内 |
| 按钮文本用正则 | 按钮可能含空格/特殊字符，如 "保 存" |
| 节点选择用模糊匹配 | 节点卡片标题+描述混排，不能精确匹配 |
| DOM可见性双检 | 存在≠可点击，必须检查 boundingRect + display |
| 菜单展开分两步 | expandSubMenu + clickMenuItem，中间插入 1500ms 等待 |

## 12. Ant Design 菜单导航（实战范式）

### 标准交互模式

F88 左侧导航使用 Ant Design Menu 组件，子菜单需先展开再点击：

```javascript
// ── 封装：Ant Design 菜单导航标准范式 ──
async function navigateToPage(page, submenuText, menuItemText) {
  // Step 1: 展开子菜单
  await page.evaluate((text) => {
    const titles = document.querySelectorAll('.ant-menu-submenu-title');
    for (const t of titles) {
      if (t.textContent.includes(text)) {
        t.click();
        return;
      }
    }
  }, submenuText);
  
  // Step 2: 等待 DOM 更新（关键！）
  await new Promise(r => setTimeout(r, 1500));
  
  // Step 3: 点击菜单项
  await page.evaluate((text) => {
    const items = document.querySelectorAll('.ant-menu-item .ant-menu-title-content');
    for (const item of items) {
      if (item.textContent.includes(text)) {
        item.click();
        return;
      }
    }
  }, menuItemText);
  
  // Step 4: 等待页面加载
  await new Promise(r => setTimeout(r, 3000));
}

// 使用示例
await navigateToPage(page, '审核管理', '审核标准管理');
await navigateToPage(page, '审核管理', '审核节点管理');
await navigateToPage(page, '审核管理', '任务管理');
```

### 回归测试中的教训

| 问题 | 原因 | 解法 |
|------|------|------|
| 子菜单不可见 | 未点击 submenu-title 展开 | 先 expand 再 click |
| `waitForTimeout` 已废弃 | puppeteer-core 新版 | 改用 `setTimeout` + Promise |
| 菜单项点击无效 | DOM 未更新完成 | 插入 1500ms 等待 |
| 页面未加载完 | 网络延迟 | 插入 3000ms 等待 |

## 13. 登录与认证（实战经验）

### MFA/可信设备问题
- 首次登录会触发 MFA 可信设备认证，自动化无法处理
- **解法**：手动登录一次 + CDP 调试端口启动，复用登录态

```bash
# 启动带 CDP 调试端口的 Chrome
/Applications/Google\ Chrome.app/Contents/MacOS/Google\ Chrome \
  --remote-debugging-port=9222 \
  --user-data-dir=/tmp/chrome-debug
```

### 租户验证必须放在用例首步
- 每个用例第一步必须验证页面包含“F88”和“运营平台”文本
- 确保租户身份正确后才进行后续操作
