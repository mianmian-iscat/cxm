# 晋升评价简评范例

本文件收录历史晋升评价的简评范例，按候选人画像分类，供撰写评审报告时参照风格、结构和密度。

> 配套文件：简评写作公式和类型学见 [promotion-report-template](promotion-report-template.md)（简评撰写指南章节）。

**综合判断**部分必须包含以下内容：
- 初步判断：满足/不满足晋升基本条件
- **符合新层级要求的关键点**（2-3 条）
- **尚不符合晋升要求的方面**（1-2 条）

---

## 一、技术深耕型

长期在一个技术方向深耕，产出有深度，技术创新带来量化结果。

### 范例 1（端体验性能优化方向）

做的好的：
- 长期在酒店客户端团队持续打磨端体验，初步做到了 App 酒店交易链路的秒出，可交互时间降低至 0.7s 以内，主导设计沉淀了可复用的优化方案 performanceKit。很好地符合 P7 对"主导端到端完整解决方案，通过技术上的创新取得显著结果"的要求。
- 另外业绩层面，作为主力研发支撑商详 2.0 全类目覆盖的重构，丰富了行业表达，在技术复杂性和协同难度上有较高的挑战的情况下，也有很好的输出。

有待提升的：
- 提升表达能力，要敢于发起对话，合理应对组内与业务搭档之间沟通协作问题，在体验问题和效率追求上不轻易妥协，不怕冲突，主动推动。从 P7 层级对于"主动协同上下游组织发起专项并完成里程碑交付"的要求来看，有一定的提升空间。
- 在视野和责任感方面，对于 performanceKit 在多行业的推广要加强，担起行业侧架构师的职责，影响更多类目交易链路达成秒出体验。P7 对于技术性架构师要求之一是"复用性技术方案带来增量收益"，这一点上也可以做得更好。

### 范例 2（深度技术 + 业务衔接方向）

做的好的：
- 长期作为火车票前端的核心研发，在端直连体系、协助协议破解、并基于此落地正逆向全链路端直连能力，为火车票业务的发展做出了突出贡献，在架构设计的个别方面已经达到业内前沿水平。
- 另外注重技术创新和业务结果之间的衔接，其中一项成果获得了 Serverless 挑战赛冠军。很好地匹配下一层级关于"识别定义当前核心问题制定策略并推动落地，在技术层面有极高的价值"的要求。

有待提升的：
- 格局视野方面，由于长期处于单兵或 mini 团队作战阶段，缺少影响周围人的意识和方法。在 P7 层级关于"推动上下游形成合力促进成功"以及"参与业务规划"两个要求上，要有更多的意识上的破冰，跨越技术和组织边界，思考如何把单点的突破转变为面的优势，推动"散装架构"的进一步优化升级，把"技术赢"带向"业务赢"。

### 范例 3（端侧稳定性与架构治理方向）

做的好的：
- 长期在客户端基础线做稳定性和架构治理工作，近一年半投入在动态化方案的建设，高质量完成了解析后的内存映射以及配套工具建设，同时在代码混淆、事件总线模型以及相关重构方面都有非常扎实的输出。为客户端动态化能力建设作出重要贡献。
- 主动承担了大量架构腐化代码治理，在保障架构层面的合理性、稳定性和上层应用支撑方面起到了关键作用。从下个层级要求看，对于"所处环境、问题难度和交付复杂度"的角度看，能力上是很好的匹配的。而且最重要的，这些工作大都是在幕后，这种好习惯和技术坚持非常难得。

有待提升的：
- 也正是因为长期从事基础性"幕后"工作，更要注重和前线研发及产品同学的交流和互动，必须要走前线、听声音，特别是技术产品在前线业务中的使用体感要有觉察。P7 层级在协同能力上的要求是"领导团队内中大型项目，发现并解决关键难题，方案为他人复用"，这方面的"主动意识"要加强。
- 架构师能力进一步提升，除了提升自己提炼关键问题的能力，还要站在架构演进的规律和方向上具备前瞻性，多做分享和布道，从基础线架构师迈向全局架构师。

## 二、平台架构型

搭建通用能力，影响多个业务域，沉淀组件和框架。

### 范例 4（平台通用能力方向）

做的好的：
- 在专项治理战役中承担重要角色，其中推动工单承接效率提升以及归因分析等工作十分到位，平台业务体验重灾区的专项治理工作按期交付，在下单报错率和下单一次性成功率等指标上均有正向影响。
- 此外在端侧平台通用能力打造方面，有大量业务组件沉淀积累，包括关键组件的改造，同时推动核心场景的框架升级，提高了产研效率。在对 P7 的要求中"通过合理选型改进业务迭代效率或降低跨栈研发成本"这一点上，是做得非常不错的。

有待提升的：
- 更多参与业务技术规划，在问题域的定义、成体系的技术规划输出方面要有更高要求。P7 层级在专业度方面第一个要求是"参与业务规划，充分理解业务目标和策略，高 ROI 支撑交付"，如何在一个人维护通用组件对接多个类目时，更好地针对研发瓶颈给出技术性解法。
- 团队协同方面，尤其是和前线类目同学的协作中，要敢于做交付承诺、文档配套以及腐化代码的及时重构。跨团队沟通上要充分，要能很好地化解协作冲突。

### 范例 5（容器与跨端架构方向）

做的好的：
- 作为容器负责人，在多技术栈的现状下，做到了容器侧高效稳定的运维支撑，完成容器架构的数次重构，在关键基建上有突出贡献，且收获协同方的普遍好评。在下个层级要求上有两点是很好的匹配的：第一是"通过合理技术选型改进业务迭代效率或降低跨栈研发成本"，第二是"技术突破在跨业务场景或跨团队可被复用，产生一定的技术影响力"。
- 团队协同方面，努力克服了跨地域协作困难，尽管过程坎坷，但最终解决了关键问题，拿到阶段性成果。

有待提升的：
- 提升技术视野，主动增加跨地域沟通频度，增加自己的信息渠道来源，以辅助自己做技术决策和判断，把良好的技术口碑在整个团队层面建立起来。对于 P7 架构师来说，要在技术规划之初就了解全局、主动补齐一手信息，不等不靠。
- 专业度方面要有更高要求，除了防守性质的"维稳"之外，更要走基层，架构设计上要有前瞻性，并善于总结提炼，做更多的向上沟通。下个层级的要求是"参与到业务规划，协同上下游组织发起专项"，这其中就包括了目标和策略的制定、技术带来增益的衡量等。

## 三、业务紧贴型

紧贴业务场景，客户口碑好，数据驱动决策。

### 范例 6（业务敏感 + 技术规划方向）

做的好的：
- 业务支撑方面，长期在客服一线研发，积累了大量提升服务体验效率的产出，客户有极佳的反馈。比如通过 SOP 解决方案有效解决客服服务成本并提升操作一致性，通过性能优化方案解决系统卡顿问题，客服小二的反馈极佳。这体现了很好的业务敏感性，也很好的匹配下一层级关于"深入学习借鉴行业经验解决现有难题或完善体系"的要求。
- 另外积极参与微前端方向的共建工作，长期以来推动了统一微前端框架的落地，体现了很好的技术判断力和执行力。在技术规划落地方面很好地匹配 P7 在"识别当前域的核心问题制定策略，找到突破点，推动落地拿结果"的要求。

有待提升的：
- 除了纯技术层面的输出，在紧靠业务的技术规划方面也要有更多输出和体现。以微前端为例，当下中后台方向对功能层面的模块级解决方案有更强烈的诉求，比如菜单权限、整体换肤、更灵活的页面嵌套，以及老旧系统的改造等方面依然很大程度影响体验和效率。P7 层级的要求是"在理解业务的基础上参与规划、合理选型，系统性解决关键问题，进一步在业务层面带来可衡量的价值"，这一点上有很大提升空间。

### 范例 7（数据驱动 + 体验治理方向）

做的好的：
- 作为酒店域的核心研发同学，推动实施酒店交易链路 H5 的性能体验优化，跳出技术栈的限制，对接口的串并行逻辑合理性和耗时做了详细的分析，做了大量有针对性的优化，做到酒店详情 H5 的 2s 达标率达到 90%，下单 2s 达标率 85%。
- 推动完善酒店场景化搭建能力，把通用导购能力在酒店场景做了很好的延伸，以较低成本提升了运营的体验和效率。
- 快速搭建了酒店域导购数字看板，使用频率极高，得到搭档们的一致好评。体现了"有规划"、"有计划"、"紧贴业务场景"的务实行动力，很好地匹配 P7 对于"理解业务参与业务"、"结合规划定义问题"等方面的要求。

有待提升的：
- 视野上需要提升，要多和竞对比、和行业顶尖比。比如性能指标和自己过去比虽然已经做到很好，但要树立更高的目标，把竞对作为需要超越的对手，在树立更高目标方面要更有野心。

## 四、PM 攻坚型

临危受命或从 0 到 1 交付，跨团队协调，拿里程碑结果。

### 范例 8（从 0 到 1 攻坚方向）

做的好的：
- 业务结果方面，作为微信小程序一期执行 PM，从 0 到 1 攻坚完成域名、登录和接口、性能监控等难题的攻克，很多方案属于集团内首次吃螃蟹，输出了各行业通用的解决方案，上线后也收获很好的业务结果。
- 技术贡献方面，推动搭建能力建设，站在导购搭建场景的角度，面对各行业导购整合的技术难度，结合现有搭建和投放能力，完成平台建设，做到了搭建能力的可配置、可移植、可定制，扩展出了大量好用的场景搭建工具，影响深远。在"规划解决，落地执行"方面很好地体现了 P7 的要求。

有待提升的：
- 要站在更大的职责范围承担责任，比如和各行业的配合，以及对技术选型方面的坚持要更加笃定并敢想敢讲，除了敢承诺之外，还要对协同方提更高要求，期待未来能产出更多技术成果，推动方向健康良性的发展。

### 范例 9（大促技术引领方向）

做的好的：
- 营销导购会场的前端一号位，在历届大促中作为端侧 PM 均有良好表现，特别是作为双十一大促前端 PM 和会场秒出战役的前端负责人，带领团队拿到"飞常战队"奖，相比 618 的性能体验的一般表现，在双十一期间大幅提升会场体验性能，并做到肉眼直出，是非常值得肯定的。在下个层级"促进上下游形成合力"方面具有一定的感染力和带动力。
- 在技术引领方面，对搭建侧的 SSR 渲染技术的实施有较为全面的规划，在大促中的应用也比较成功，很多方案沉淀下来亦能对更多业务域的 H5 SSR 改造起到很好的样板作用和借鉴意义。

有待提升的：
- 虽然口碑和人缘比较好，做事仍然需要有更多的攻击性和更多方向性的引领，定义更高的目标，并在关键站位中敢于担责。比如会场秒出目标应当对标行业一梯队的竞对，和自己比要大胆地提出并坚持通过录屏读秒来还原真实体感。期待在目标设定上可以有更高要求和更犀利的表现。

## 五、创新突破型

引入新技术/新方案，有前瞻性，方法论可沉淀。

### 范例 10（端智能/创新方向）

做的好的：
- 长期主导端智能方向，引入了集团端智能解决方案，解决了端侧模型下发实时性的问题，在多个业务场景中植入运用，带来非常好的使用体感，对各域转化率数据均有正向影响。在长期坚持下，拿到这样的成果很难得，方法论也被沉淀整理成论文发表在学术会议并被索引。
- 项目贡献方面，作为 PM 推动推荐模块统一化项目，推动了推荐模块的场景覆盖，单坑 UVCTR 的提升幅度在 10% 到 40% 不等。擅长担任跨团队 PM，能很好地做到 P7 对于"协同各方发起专项并完成里程碑交付"的要求。

有待提升的：
- 一方面接下来要更加聚焦，参与业务决策和共创讨论，提升技术视野。下一层级对于"参与规划、主动发现技术支撑存在的瓶颈，并推动架构升级"等方面要求更高，要主动参与进去。
- 另一方面要积极参与团队技术文化的建设，带动打造更好的团队技术氛围。

## 六、综合型 / 稳定性守护者

兼具多面能力，或在幕后保障系统稳定运行。

### 范例 11（综合选手方向）

做的好的：
- 定位为一名"综合选手"，既在小交通方向承担核心研发职责，也多次临危受命支撑重要业务。特别是在某业务上的补位，不仅很好地承接原有研发迭代，还发起稳定性治理专项，有很好的成绩。
- 有不错的技术方案化繁为简的能力。业务重压之下也能保持技术动作不变形，也有通过前端 AI 能力帮助业务合规识别率提升的好案例。
- 小交通业务方面贡献卓著，特别难得的是主动带领前端小伙伴去一线走访现场拿到一手资料，线下链路的体验是可以跟竞对扳手腕的。这种紧贴客户的求真精神值得肯定。

有待提升的：
- 要对业务数据和规划等重要输入给予更多关注，和内部搭档们的协作更加紧密，提升对内影响力。除了保持执行力上的好的特质，要"在深度理解业务的基础上参与规划"，更多的做中长期的技术规划。

### 范例 12（工程体系与架构守门人方向）

做的好的：
- 临危受命承担起了前端工程体系化建设的重任，并重点支持了小程序一码多端等方案的落地，保障了上层业务的稳定，研发者有体感，技术上有深度。
- 此外在机票业务中作为核心开发，克服巨大的人日成本压力，以 PM 角色推动完成微信小程序的如期交付，在上线初期未做推广的前提下即拿到日均订单量 700+，至此完成一体化小程序最后一块业务域的拼图。收获协作方的高度认可，也体现了 P7 层级对协作共赢方面的要求。

有待提升的：
- 由于前端架构师的角色需要，对于重大技术方向的选型和实施，需要形成自己的判断，不要做"老好人"，对于一些对架构和底层代码不合规范甚至"破坏性"的变更，要敢于说不，守好基础库的质量大门。
- 对于架构师和 PM 来说，需要进一步扩大视野，学习借鉴他山之石，除了守成之外，争取在技术设计理念的先进性上兼容并包，对于产品体验的关注要对标竞争对手，对于技术的实施要多研究 AI Coding 等新领域，提高目标要求，大胆尝试。

## 七、不同改进方向的范例

以下范例聚焦"有待提升的"写法，展示如何针对不同短板精准引用 JobModel。

### 范例 13（改进方向：ROI 意识 + 业务理解）

有待提升的：
- 在 SOP 的体系建设方面，要获取更多业务层面的输入，定义难题，在此基础上结合自己的方向来针对性的解决难题。结合 P7 对于"在自身领域中结合业务现状和规划来定义问题"的要求来提升自己。建议更多地参与决策过程和规划，保持向上沟通，更加聚焦问题本质，有意识地控制体系建设的整体 ROI，这在未来会更好地帮助自己准确切中痛点、拿到更多好的成果。

### 范例 14（改进方向：跨地域协同 + 架构师影响力）

有待提升的：
- 在团队协同方面，尤其是在跨团队跨地域跨角色的推动协同方和合作伙伴时，要更有要性和方法，主动提高自己布道能力和事情的推动力。在面对不确定性的工作时及时调整，不要有畏难情绪。比如长期以来作为前端性能整治行动的推动者，对于前线业务的参与深度和配合体感方面，作为 PM 要更有责任感和推动力。P7 层级对于"主动协同上下游促成成功"的要求是可以做得更好的。

### 范例 15（改进方向：业务视角 + 竞对对标）

有待提升的：
- 第一，落地后需要全面的复盘，尤其是在 ROI 投产比方面做复盘，数据论证和结论之间的逻辑略显模糊，难以对后续演进方向做准确判断。按照 P7 对"考虑技术投产比 (ROI)"的要求看，可以做得更好。
- 第二，作为业务侧研发，需要适当转变到业务视角，从产品完善度和客户需要去理解体验痛点，特别是通过和客户的直接接触来加深业务理解，借此帮助自己完善技术规划。
- 第三，按照晋升要求，要多和竞对比、和行业顶尖比。升级专项除了和自己过往比，应当多和竞品来对比，比用户口碑、功能完善度和体验顺滑度。
