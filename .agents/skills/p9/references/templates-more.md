## 模板 21：项目发布信（Release Letter）

适用场景：一个重要项目上线/发布后，需要向全团队（包括支援方）发一封正式的 Release 信。这封信同时是里程碑标记、感谢函和成果通告。

### 写作结构

```markdown
# {项目名称} {阶段} Release

{开场：选择有意义的时间节点（如 1024 程序员节），一句话宣布结果。语气是兴奋但克制的。}

例：在这个程序员的节日里（1024），{项目名}的入口正式打开（集团内灰），项目迎来了一个重要的里程碑。给为项目付出的各位同学点赞！！！

## 项目背景（一段话）

{用 1-2 段话讲清楚：}
- 这个项目为什么重要（战略意义）
- 核心做了什么（产品/技术层面的概括）
- 为什么值得骄傲（颠覆性的变化是什么）

{风格要求：用"一直以来...都属颠覆性的"这种句式建立叙事感。避免罗列功能清单。}

## 项目过程（一段话）

{讲述项目的挑战：}
- 什么时候立项、多少人参战、团队怎么拼凑的
- 最大的挑战是什么（磨合、沟通、技术选型）
- 怎么扛过来的（"太多小伙伴挺身而出、勇于担当、迎难而上"）

{风格要求：}
- 用"我和XX开始谁都没底这个项目会做成什么样"这种坦诚的语气
- "由衷的感谢大家，赞赏大家的这份专业和执着"——真诚的感谢
- 可以单独给特别贡献者点赞（但不宜太长）

## 当前状态和后续计划

{诚实说明当前状态：}
- 现在是内灰/全量/什么阶段
- 还存在哪些已知问题
- 下一步的修复/发布计划
- 问题反馈渠道和联系人

## 收尾

{一句话鼓舞士气，可以用业务目标作为口号。}

例：{项目名}一个亿，走起！！！
```

### 写作原则

- **有温度**：不是冷冰冰的项目报告，是写给所有参与者的感谢信
- **有诚意**：承认过程中的艰难，不是只报喜
- **有细节**：点名感谢具体的人（特别是支援方和幕后英雄）
- **有后续**：告诉所有人"接下来怎么办"
- **控制在 1 页以内**：Release 信不是总结报告

### 范例结构（来自出境超市一期 Release）

> 开场：节日节点 + 一句话宣布上线 → 背景：为什么重要（颠覆性变化）→ 过程：百人大战的挑战 → 感谢：点名+礼物+生活委员 → 当前状态：内灰 + 已知问题 + 周五修复版 → 收尾："出境超市一个亿，走起！！！"

## 模板 22：跨团队大项目 KO（PPT 结构）

适用场景：启动一个跨多个部门/BU 的大型对齐项目，需要用 PPT 向管理层汇报 KO。区别于模板 13（markdown KO 文档），这个模板是**演示文稿结构**。

### PPT 页面结构

```
## Slide 1：项目定位与目标
- 项目名称
- 一句话定位（这个项目要解决什么结构性问题）
- 两个核心目标（效率目标 + 覆盖目标）
  - 例：核心系统端到端效率提升不低于 40%
  - 例：全系统端到端效率提升 30%
- 标杆案例产出要求（每月各领域输出标杆案例）

## Slide 2：现状盘点
- 当前系统/团队的数量级数据
- 成熟度分布（用五级模型或红黄绿灯）
  - 例：接近 55% 在 L1，约 30% 在 L2，中级及以上仍是少数
- 按域/按团队的现状矩阵图
  - 每个负责人管理多少系统，当前 L 级分布，目标 L 级

## Slide 3：项目拆解（按业务域）
- 按业务域（非技术层）拆解
  - 每个域：负责人、系统数、当前状态、目标状态
  - 例：酒店域 XX 个系统，度假域 XX 个系统...
- 里程碑节奏
  - 例：615 里程碑 → 830 里程碑 → 年底目标

## Slide 4：组织保障与汇报机制
- 指挥体系（谁是大 PM、谁是各域 PM）
- 汇报节奏（月度里程碑汇报 + 域级周报）
- 度量方式（从覆盖率转向交付效率、缺陷率）
- 风险预案
```

### 写作原则

- **从数据开始，不从愿景开始**：老板不缺方向感，缺的是"从哪出发"的证据
- **按业务域拆解，不按技术层**：让每个业务负责人看到自己域的全貌
- **设定阶段性里程碑**：不是"年底达成目标"，而是每 2-3 个月有可检验的检查点
- **度量指标要进化**：初期用覆盖率/成熟度，后期转向效率/缺陷率/人均产出

## 模板 23：里程碑汇报（PPT 结构）

适用场景：跨团队大项目进行到某个里程碑节点（如 615、830），需要向管理层汇报阶段进展。

### PPT 页面结构

```
## Slide 1：整体进展概览
- 一句话总结本里程碑的整体状态
- 关键数字变化（本里程碑 vs 上里程碑 vs 目标）
  - 例：L3 及以上系统占比从 X% → Y%（目标 Z%）
- 红黄绿灯状态标记

## Slide 2-N：各域进展（每个域一页）
每页结构：
- 域名称 + 负责人
- 本域系统数量和目标完成率
- 2-3 个亮点项目（具体效率数据）
  - 例：{项目名}效率提升 35%，AI Co-Authored 占比 70%
- 1-2 个风险/问题
- 可视化进展（截图/GIF/数据对比图）

## Slide N+1：标杆案例
- 选 2-3 个最佳实践案例
- 每个案例：项目背景 → 做了什么 → 效率数据 → 可复制性分析
- 标杆案例的共性特征提炼

## Slide N+2：下一里程碑计划
- 下阶段目标（具体数字）
- 需要管理层介入/决策的事项
- 资源/协调需求
```

### 写作原则

- **数字先行**：每个域先报数字，再讲故事
- **红黄绿灯**：让老板一眼看到哪些域健康、哪些需要关注
- **标杆案例要有可复制性**：不是"某某团队很厉害"，而是"同层级的人可以复制这个方法"
- **直面差距**：与目标的差距要明说，不要藏在细节里

### 范例结构（来自超级对齐 615 里程碑）

> 整体概览 → 交通域进展（38 个系统，66% L2，34% L1 → 目标 76% L3）→ 度假域进展 → 用户域进展 → 酒店域进展 → 标杆案例 3 个 → 下一里程碑（830）目标 → 需要决策的事项

## 模板 24：战役结项总结（M4 报告）

适用场景：一个贯穿半年到一年的大型战役/项目结项（M4 = Milestone 4 = 结项标志），需要用**结构化表格**向一线员工呈现结果，并给同级同事参考。适合用 Excel 或结构化文档呈现。

### 报告结构

```markdown
# {战役名称} 结项总结（M4）

## 一、战役总体数据

| 指标 | 目标 | 实际 | 达标率 |
|------|------|------|--------|
| 需求总数 | - | {X} | - |
| 交付数量 | - | {X} | {X}% |
| 需求达标量 | - | {X} | {X}% |
| 缺陷总量 | - | {X} | - |
| 人力投入 | - | {X} 人月 | - |

## 二、分项目明细

| 战役 | 项目 | 项目目标 | 子项目 | 已完成/需求数 | 达标数 | Bug数/遗留 | 人力(人月) | 子项目达标 | 目标达成 | 技术/产品总结 |
|------|------|----------|--------|-------------|--------|-----------|-----------|-----------|---------|-------------|
| {战役名} | {项目1} | {量化目标} | {子项目A} | X/Y | Z | W/V | N | {达标/部分达标/未达标} | {达标/部分达标/未达标} | {能力沉淀总结} |
| | | | {子项目B} | | | | | | | |
| | {项目2} | | | | | | | | | |

## 三、总体回顾

### 达成情况（第一人称叙述）

{用"总的来看"开头，按 3-5 个维度总结本期成果：}

第一，{维度1}方面，{具体数据和判断}
第二，{维度2}方面，{具体数据和判断}
第三，{维度3}方面，{具体数据和判断}
...

### 两期（或多期）战役带来的变化

{用跨期对比展示累积效果：}

第一，{变化1}：经过{N}期持续优化，{指标A}从{X}到{Y}
第二，{变化2}：{指标B}增幅明显，{具体数据}
第三，{变化3}：{趋势性判断}

### 不足

{诚实列出 3-4 个不足：}

1. {不足1}：{具体描述 + 根因}
2. {不足2}：{具体描述 + 根因}
3. {不足3}：{具体描述 + 根因}
```

### 达标判断标准

| 判断 | 条件 |
|------|------|
| **达标** | 核心指标全部达成，无遗留技术问题 |
| **基本达标** | 核心指标达成，但有非关键遗留项 |
| **部分达标** | 部分核心指标达成，部分未达成 |
| **未达标** | 核心指标多数未达成，或项目被取消 |

### 写作原则

- **每个子项目都有技术/产品总结**：不是只报结果，要说清楚留下了什么能力沉淀
- **达标情况必须具体**：不写"基本完成"，写"春运玩法端内 UV 峰值 138 万，日均留存 38%，7 日回访率 63%"
- **不足要归因**：不是"还有提升空间"，而是"本次战役仍然聚焦在 App 端，手淘和支付宝端未涉及"
- **跨期对比**：与上一期的数据放在一起比，让趋势可视化

### 范例结构（来自体验战役二期 M4）

> 表格明细（6 个大项目，20+ 子项目）→ 汇总数据（311 需求/251 交付/57% 达标率/113 人月）→ "总的来看"五段总结 → "两期战役带来的变化"三段跨期对比 → 四个不足

## 模板 25：年度技术规划（PPT 结构）

适用场景：为技术团队制定年度（财年）规划，需要以 PPT 向管理层汇报。区别于 templates.md 中的 Strategy Plan（markdown），这个模板是**演示文稿结构**，保留了拔赤的行文风格。

### PPT 页面结构

```
## Slide 1：封面
- {团队名} {财年} 技术规划
- 作者 + 日期
- 副标题（可选，一句话概括本年度主题）

## Slide 2：业务上下文（为什么）
- 业务现状数据（DAU/MAU/GMV 趋势图，同比对比）
- 竞争对标（vs 主要竞品的关键指标对比）
- 流量结构分析（各渠道占比饼图）
- 本年度业务目标（从业务方承接的目标）

{拔赤风格：每页至少 3 个具体数字，用括号加同比变化。"DAU 稳中带升（同比 +15%）"}

## Slide 3：上年度回顾（承上）
- 上年度关键成果（按域分列，每个域 1-2 句话 + 数据）
- 上年度遗留问题（坦诚列出，不回避）
- 从上年到本年的逻辑衔接："基于上述成果和不足，本年..."

{拔赤风格：用"承上启下"作为结构性转折。成就不浮夸，不足不掩饰。}

## Slide 4：核心挑战（是什么）
- 3 个核心挑战（不超过 3 个，每个有子项）
  - ① {挑战1}：{2-3 个子项}
  - ② {挑战2}：{2-3 个子项}
  - ③ {挑战3}：{2-3 个子项}

{拔赤风格：挑战用"第一...第二...第三..."编号。每个挑战不是抽象问题，而是"具体矛盾 + 为什么现在必须解决"。}

## Slide 5：战略方向（怎么做）
- 3-4 个战略方向（用四字动词短语概括）
  - 例：提升留存、拓宽流量、塑造差异、沉淀能力
- 每个方向下有 2-3 个子项，行动 → 结果 格式
- S1/S2 里程碑标注

{拔赤风格：战略方向用并列动词短语（四字格），朗朗上口。每个方向有明确的量化目标。}

## Slide 6：技术演进路线（架构演进历程）
- 多年架构演进时间线（不只本年，展示 3-4 年的演变）
  - 例：1.0（简单）→ 2.0（MPass）→ 3.0（Mashup App）
- 每个阶段标注：团队规模、技术栈、核心挑战
- 本年架构目标在时间线上的位置

{拔赤风格：不是只画目标架构，而是展示"从哪来到哪去"的完整旅程。让老板看到技术演进的逻辑。}

## Slide 7：组织与资源
- 团队人力规划（headcount 变化）
- 组织结构变化（如有）
- 资源投入分配（按域的投入比例）
- 关键人才梯队

## Slide 8（可选）：四大战役/关键项目
- 如果本年度有几个大战役，单独一页列出
  - 每个战役：名称、目标、负责人、时间节点
- "四大战役"这种命名增加记忆点
```

### 行文风格指南

1. **数据密度高**：几乎每个 bullet point 都有具体数字，用括号加同比/环比
2. **竞争对标常态化**：时时与竞品数据对比，不是为了焦虑，是为了校准
3. **三件套分组**：默认用三个一组来组织信息（"三大挑战""三个方向""三期演进"）
4. **四字格动词短语**：战略方向用四字短语（"提升留存""拓宽流量"），增加节奏感
5. **括号补充说明**：频繁用括号补充上下文（"艰难的转型期""首次打通"）
6. **技术术语精确但业务结果先行**：先说业务结果（转化率 +3%），再说技术手段（动态模板）
7. **承上启下**：每页之间有逻辑衔接，不是孤立的幻灯片

## 模板 26：年度述职汇报（PPT 结构）

适用场景：年终向管理层做述职汇报（D 级汇报）。区别于模板 25（规划），述职是回顾性质，需要展示成果 + 反思不足 + 展望下年。

### PPT 页面结构

```
## Slide 1：述职大纲
- 组织规定的述职框架（通常 5 个部分）
  - ① 上年度 OKR 完成概述 + 根因分析
  - ② 新年度业务规划对齐情况
  - ③ 新年度组织结构、干部选用、编制规划
  - ④ 核心人才盘点
  - ⑤ 当前干部梯队、缺口和组织策略

## Slide 2-3：OKR 完成情况（按领域展开）
每个领域结构：
- **完成情况**：{做了什么，数据如何}
- **思考（反思框）**：{坦诚的反思，不回避问题}

{拔赤风格：每个成就板块旁边有一个"思考"侧栏，坦诚说"有惊无险"或"还不够"。成就不浮夸，反思不掩饰。}

例：
- **重点项目交付**：
  - {项目A}：效率提升 35%，提前交付
  - {项目B}：覆盖 XX 个系统，AI Co-Authored 占比 70%
  - 🤔 思考：{项目C}的推进节奏偏慢，根因是跨团队协调成本高

## Slide 4：下年度工作重点
- 3 个方向，每个有量化目标
  - 方向1：{目标数字}
  - 方向2：{目标数字}
  - 方向3：{目标数字}

## Slide 5：组织策略
- 挑战与风险
- 应对策略
- 团队层级分布饼图（P5/P6/P7/P8/P9 占比）
- 关键岗位盘点
- 干部梯队规划
```

### 行文风格指南

1. **成就 + 反思双栏**：每个成果板块必须有"思考"侧栏。不是"还有提升空间"这种废话，而是具体的根因分析
2. **三句话开场**：用三个高密度 bullet point 概括全年，每个覆盖不同领域
3. **前瞻性桥梁**：每个板块结尾连接到下年——"这为明年的XX奠定了基础"
4. **组织数据可视化**：团队层级分布用饼图，标注具体百分比
5. **坦诚的不足**：用"有惊无险的挺过XX"这种语气，承认过程中的险象环生

### 范例结构（来自 FY21 年度述职）

> 述职大纲（5 点）→ OKR 完成（4 个领域 × 成就+反思）→ 下年重点（3 个方向 × 量化目标）→ 组织策略（挑战+风险+策略+层级分布图）

## 模板 27：管理共创会

适用场景：组织中高层管理者（TL/P8+）的管理共创会。区别于模板 14（技术共创会），管理共创会聚焦于人、组织、领导力，而非技术方案。

### 共创会结构（多年实践提炼的统一框架）

```markdown
# {主题} — 管理共创会

**日期**：{date}
**参与人**：{D 级管理者 + 核心 TL}
**形式**：{半天/全天}

## 一、回顾与衔接

{如果是系列共创会，先回顾上一次的核心要点和遗留问题，建立连续性。}

例：过去四年的管理共创：
- {年份1}：{主题}
- {年份2}：{主题}
- {年份3}：{主题}
- {年份4}：{主题}

## 二、我们在哪里（宏观上下文）

{将管理者放入更大的上下文中：}
- 行业趋势/公司战略变化
- 团队面临的核心矛盾
- 用一张图或一个比喻概括当前状态

例：
- 宏观：{行业/公司层面的变化}
- 微观：{团队层面的具体挑战}
- 核心矛盾：{用一句话概括}

## 三、核心议题（理论 + 案例 + 讨论）

### 理论框架

{引入一个管理理论/模型作为讨论的脚手架。不是讲课，是给讨论一个共同的坐标系。}

{常用框架：}
- 科学管理 vs 现代管理的演进对比（Taylor vs Drucker）
- PM 四象限模型（对上/对下/对客户/对合作伙伴）
- 九型人格作为管理工具
- "让听到炮声的人做决策"的组织原则

### 案例研讨（核心环节，2-4 个案例）

每个案例结构：

#### 案例 {N}：{脱敏标题}

**当事人诉求**：
{用当事人自己的话描述 TA 想要什么}

**实际达成情况**：
{理想与现实的差距}

**内在动因**：
{为什么 TA 有这个诉求？驱动力是什么？}

**管理者的评估**：
{从多维度评估当事人的状态}

**路径设计**：
{管理者为 TA 设计了什么成长路径}

**遇到的困难**：
{路径执行中的阻碍和偏差}

**管理盲区**：
{管理者在这个过程中忽略了什么}

**管理反思**：
{如果重来，可以怎么做不同}

**管理洞察（抽象提炼）**：
{从这个案例中提炼的通用管理原则}

**行动项**：
{具体的沟通话术和下一步动作}

### 互动讨论

{每个案例后的开放讨论。可以设置引导问题：}
- "如果你是 TA 的管理者，你会怎么做？"
- "这个案例中，管理者的盲区是什么？"

## 四、工具箱

{给管理者可以直接带回团队使用的实用工具。}

{常用工具箱：}
- **三种版本的自我表达**：5 秒版 / 30 秒版 / 5 分钟版
- **论文格式框架**：引言 → 选择 → 方案 → 成果 → 展望
- **ROI 换算成钱**：把技术决策换算成人天、预算、转化率影响
- **提问的正确方式**：先展示自己的思考 + 给出具体数据 + 缩窄范围
- **找一面镜子**：找一个能给诚实反馈的同级

## 五、总结与作业

### 管理锦囊（编号列表）

{将全天讨论浓缩为 N 条管理锦囊。每条一句话 + 一行解释。}

1. {锦囊1}：{一句话解释}
2. {锦囊2}：{一句话解释}
3. ...

### 课后作业

{给参与者布置具体的管理动作，要求在一定时间内完成并回报。}

- 作业1：{具体动作} — 完成时间：{date}
- 作业2：{具体动作} — 完成时间：{date}
```

### 四种沟通原型（管理共创会常用工具）

| 类型 | 特征 | 沟通策略 |
|------|------|----------|
| **头狼（Star）** | 能力强、野心大 | 激发 → 让 TA 自己说出理想蓝图 |
| **野狗（Wild Dog）** | 能力强、行为出格 | 公开 review → 对齐 TA 的自我认知与他人认知 |
| **平庸（Mediocre）** | 能力一般、态度好 | 建设 → 消除恐惧，建立信心，帮 TA 定义清晰目标 |
| **迷失（Lost）** | 曾经优秀、现在迷失 | 破冰 → 打破心智模型，让 TA 动起来，拉 TA 入局 |

### 管理共创会的核心原则

1. **从真实案例出发，不从理论出发**：每个理论框架必须紧跟真实案例
2. **管理盲区比管理动作更重要**：讨论的重点不是"该怎么做"，而是"我忽略了什么"
3. **沟通话术要具体到可以直接用**：不是"加强沟通"，而是"下周一 1:1 时，先问 TA：'你觉得最近最有成就感的事是什么？'"
4. **工具箱要能带走**：参与者离开时手里要有可以直接用的工具
5. **作业要有回报机制**：布置的作业必须有检查和反馈环节

### 多年共创会的演进规律

| 年份 | 主题 | 核心框架 | 风格演进 |
|------|------|----------|----------|
| 第 1 年 | 个人职业回顾 | 职业心电图 + 三次创业浪潮 | 个人叙事为主 |
| 第 2 年 | 从小乘到使众人行 | 八卦人格映射 + 五锦囊 | 从个人管理到组织管理 |
| 第 3 年 | 管理实践课 | 四沟通原型 + 案例深度拆解 | 聚焦人的管理 |
| 第 4 年 | 敏捷组织 | PM 四象限 + TL 教练法 | 聚焦组织建设 |

> 规律：每年主题从"个人"向"组织"递进，但案例研讨和工具箱是每年的固定环节。

## 模板 28：半年度述职汇报（PPT 结构）

适用场景：半年（S1 或 S2）结束时，向 D 级管理者做述职汇报。区别于模板 26（年度述职汇报），半年度述职更聚焦、节奏更快、强调"上半场做了什么 + 下半场怎么打"的衔接。

### PPT 页面结构（9 页，紧凑节奏）

```
## Slide 1：封面
- {团队名} FY{X}S{1/2} 述职
- 作者 + 日期

## Slide 2：本期工作总览（1 页，全局鸟瞰）
- 用 4 个板块概括本期全部工作：
  - 板块 A：{核心交付域}
  - 板块 B：{体验/架构/基建}
  - 板块 C：{AI 转型/创新}
  - 板块 D：{组织建设/团队}
- 每个板块 3-5 条高密度 bullet point
- 每条以"引词 + 短句"格式，包含具体数字和结果

{拔赤风格：}
- 引词格式："行业交付：完成 XX 个项目，秒开率从 X% 到 Y%"
- 不写废话，每条都带数字
- 用"完成/推动/建设/保障/优化"等动词开头

## Slide 3-4：重点工作展开（每个重点 1 页）
- 选 2-3 个本期最重要的事项展开
- 每个事项结构：
  - **背景/目标**（一句话）
  - **做了什么**（3-5 条具体行动）
  - **结果**（量化数据）
  - **沉淀**（留下了什么可复用的能力）

{拔赤风格：}
- 结果部分用"对比数据"：优化前 → 优化后
- 沉淀部分强调"方法论"和"可复制性"
- 如果结果未达预期，直接说"未达标"并给出根因

## Slide 5-6：AI 转型进展（单独 1-2 页）
- 这是 2025 年后的必选板块
- 结构：
  - 整体覆盖率/成熟度数据
  - 标杆案例 2-3 个（每个：系统名 + AI 接管深度 + 效率提升数据）
  - 基础设施建设进展（知识库/CI/Skills 覆盖率）
  - 下阶段目标

{拔赤风格：}
- 用 L1-L5 成熟度模型描述进展
- 标杆案例要具体到"XX 系统，效率提升 35%"
- 不回避问题："覆盖率到了 X% 但交付效率变化不大，说明闭环没跑通"

## Slide 7：组织与团队建设（1 页）
- 团队规模变化（入/出）
- 梯队建设进展
- 关键人才盘点（核心岗位 + 后备）
- 文化建设动作

{拔赤风格：}
- 用饼图或数字展示层级分布
- 团队建设不说空话，每条有具体动作
- "鼓励并赛跑出一批有 AI 知识储备的工程师，借事修人"

## Slide 8：S2/S1 规划（1 页，承上启下）
- 3-4 个 O（目标），每个 O 下 3-5 条 KR
- 格式与 Slide 2 一致：引词 + 短句 + 数字
- 与本期工作形成逻辑衔接

{拔赤风格：}
- 规划部分用"O1：{方向}：{一句话目标}"格式
- 每条 KR 有明确的时间节点（如"截止 730 完成"）
- 量化目标用"从 X 到 Y"格式

## Slide 9（可选）：风险与诉求
- 需要上级关注/协调的事项
- 资源缺口
- 跨团队依赖
```

### 行文风格指南

1. **引词 + 短句格式**：每条 KR 用"**引词：**描述"格式。引词是 2-4 个字的方向标签（如"行业交付"、"体验治理"、"AI 专项"、"团队建设"），后面跟一句话描述，包含具体行动和量化目标。

2. **数字密度极高**：几乎每条都有数字——百分比、天数、人月、版本号、日期。"秒开率从 65% 提升到 80%"比"显著提升秒开率"好 10 倍。

3. **时间节点具体**：不用"尽快完成"，用"截止 730 完成"。不用"下半年"，用"S2 结束前"。

4. **动词开头**：每条 KR 用动词开头——"完成"、"推动"、"保障"、"优化"、"建设"、"探索"。不用"负责"、"参与"这种被动词。

5. **量化目标用"从 X 到 Y"**：不说"提升"，说"从 65% 提升到 80%"。不说"降低"，说"降 50M"。

6. **AI 转型作为独立板块**：2025 年后，AI 转型必须作为独立板块汇报，不混在日常交付里。

7. **承上启下**：S1 述职的后半部分就是 S2 规划，S2 述职的后半部分就是下一年规划。两者在同一份 PPT 里，形成闭环。

### 范例结构（来自 FY26S1 述职）

> Slide 2 总览 → 4 大板块（行业交付/体验架构/AI 转型/组织建设）→ Slide 3-4 重点展开（超级对齐/AI Native 研发范式）→ Slide 5-6 AI 专项（L1-L5 成熟度 + 标杆案例）→ Slide 7 团队建设 → Slide 8 S2 规划（4 个 O × 3-5 条 KR）

## 模板 29：OKR 通晒模板（PPT 结构）

适用场景：在目标通晒会上展示团队半年度 OKR。区别于 okr skill 中的 KR 撰写指南（那是 markdown 格式），这个模板是**演示文稿结构**，用于在会议上向管理层和同事展示。

### PPT 页面结构

```
## Slide 1：封面
- {团队名} {财年}{S1/S2} OKR
- 作者 + 日期

## Slide 2-N：每个 O 一页（通常 4-5 个 O）

每页结构：

### O{N}：{方向标签}：{一句话目标描述}

{方向标签通常是：行业&大促 / 体验&入淘 / 架构&基建 / 团队建设 / 用户多端和服务}

{一句话目标描述：用 2-3 句话概括这个 O 的核心使命和本期要达成的状态。包含关键约束条件。}

例：O1：大住宿：支持酒店多端多场景的建设、端侧符合全链路直出性能要求；在超级对齐专项中，持续优化住宿体验槽点，拉齐和竞对差距。丰富经营工具，网关运行无故障。

#### KR 列表（每条用引词格式）

1. **{引词}：**{具体交付 + 量化目标 + 时间节点}
2. **{引词}：**{具体交付 + 量化目标 + 时间节点}
3. **{引词}：**{具体交付 + 量化目标 + 时间节点}
4. **{引词}：**{具体交付 + 量化目标 + 时间节点}

{每个 O 下通常 4-6 条 KR}
```

### KR 撰写格式详解

每条 KR 遵循统一格式：**引词 + ：+ 短句描述**

#### 引词（方向标签）

引词是 2-6 个字的方向概括，加粗显示。常见引词：

| 类别 | 常见引词 |
|------|----------|
| 交付类 | C 端交付、B 端交付、行业交付、关键交付、出海支持 |
| 体验类 | 体验治理、性能保障、搜推体验、体验专项 |
| 架构类 | 客户端架构、前端基建、平台升级、架构演进 |
| AI 类 | AI 专项、AI 生产工具、AI 创新、产品 AI 化 |
| 运营类 | 商家端、运营工具、智能搭建、数据驱动 |
| 保障类 | 春运保障、大促保障、稳定性、网关运行 |
| 团队类 | 团队建设、梯队设计、工程师氛围、用工 ROI |

#### 短句描述

短句描述的核心要素：

1. **具体交付物**：做什么（"完成智能签证交付"、"完成问一问 2.0 技术重构"）
2. **量化目标**：做到什么程度（"秒开率从 65% 到 80%"、"crash 率控制在万五以内"）
3. **时间节点**：什么时候完成（"截止 730 完成"、"S2 结束前达到"）
4. **约束条件**：底线是什么（"无 badcase"、"P3 以上故障零封"、"体验不输竞对"）

#### 范例

```
1. **火车票保障：**支持好节假日（暑期、五一、十一等）期间火车票业务平稳运行，关键岗位无专业人员的缺位，保障节假日购票体验保持在行业第一梯队。完成完善风控治理能力，解决目前候补兑现率低的问题。

2. **交通 AI 专项：**完成机票快速订票和火车票抢票王的交付，完成必要的组件库、卡片设计模式、语音多模态渲染管线、服务 Agent 的 Node 网关等核心部件的建设和沉淀，可整体外嵌和迁移，和"问一问"无缝衔接，并形成技术最佳实践。

3. **体验治理：**超级对齐专项用户域的落地，项目周期内体验问题解决率 90% 以上，完成日历选择、城市选择、通用图片浏览器等关键组件的交付。跟进猪搜端侧体验治理，做到问题清零，缩短和竞对体验差距。导购域页面性能不输携程，秒开率不低于 90%。

4. **商详的大升级：**S1 完成多 SKU 化升级，做到动静分离，对于极端场景（20+ SKU × 10 个月周期商品）也能很好的通过技术改造解决加载体验阻塞的问题，覆盖度假频道、商详、POI、订详等核心场景，秒开率不低于 85%，全场景无体验 BadCase。
```

### 行文风格指南

1. **引词加粗**：每条 KR 的引词部分用粗体，让读者一眼扫到方向。

2. **一句话内包含多层信息**：拔赤风格的 KR 不是简单的一句话，而是一个信息密度很高的复合句。一条 KR 可能包含：做什么 + 做到什么程度 + 什么时候完成 + 底线约束。

3. **具体到可验证**：不写"提升用户体验"，写"秒开率不低于 90%"。不写"加强稳定性"，写"三端 crash 率控制在万五以内"。

4. **竞品对标常态化**：频繁使用"不输携程"、"追评同程"、"行业第一梯队"等竞品对标表述，让目标有外部参照。

5. **AI 作为独立 KR 或贯穿型 KR**：AI 相关的内容要么作为独立 KR（"AI 专项"），要么贯穿在其他 KR 中（"借助 AI 能力提升运营效率"）。不要把所有 AI 工作塞进一条 KR。

6. **团队建设 O 的写法**：团队建设方向的 KR 也要具体可验证。不写"提升团队氛围"，写"通过 One One、共创会、圆桌、分享会等形式，管理团队带头 Coding"。

7. **S1 和 S2 的区别**：S1 侧重建设和交付，S2 侧重优化和冲刺。同一个 O 在 S1 和 S2 的 KR 应该有明显的演进关系。

### O 级结构参考（通用模式）

| O 编号 | 方向标签 | 覆盖范围 |
|--------|----------|----------|
| O1 | 核心业务交付 | 最重要的业务线/行业线的交付和体验 |
| O2 | 用户体验/入淘 | 面向用户的产品体验、搜索推荐、入淘等 |
| O3 | 架构与基建 | 技术底座、客户端架构、前端工程、AI 工具链 |
| O4 | 团队建设 | 人才梯队、AI 转型、文化建设、用工 ROI |
| O5（可选） | 创新/探索 | 新方向探索、跨 BU 协同、战略性投入 |

### 与 OKR 撰写指南的关系

> 本模板（模板 29）聚焦 OKR 通晒会的 **PPT 结构和行文风格**。OKR 的撰写流程、KR 格式规范、引词设计等详细指南，见 [okr-writing](okr-writing.md)。两者配合使用：okr-writing 教你怎么写，本模板教你怎么展示。

## 模板 30：月报撰写

适用场景：撰写飞猪用户技术团队月度报告。本模板提炼了月报的核心写作规范和板块结构。完整的生成流程（11 步）、团队组织结构整合、跨团队合并策略等，见 [monthly-report-generation](monthly-report-generation.md)。

### 标题层级

| 级别 | 格式 | 示例 |
|------|------|------|
| 月报总标题 | `### 飞猪用户技术月报-年-月` | `### 飞猪用户技术月报-2026-04` |
| 一级标题 | `一）二）三）` | `一）V10 项目` |
| 二级列表 | `1. 2. 3.` | `1. 架构设计：...` |
| 三级列表 | `1) 2)` | `1) 细节A...` |

**强制要求**：每个一级标题下必须使用二级列表（`1. 2. 3.`），不允许写大段不分条的段落。

### 板块结构

月报通常包含以下板块（按素材内容灵活裁剪，不必全部出现）：

| 板块 | 说明 |
|------|------|
| 体验治理/体验专项 | 性能指标、秒开率、SSR 改造、流式渲染等 |
| 端侧稳定性和安全生产 | 故障、Patch、监控、容灾 |
| 大促/营销活动 | 双十一、国庆、春运等会场数据和性能 |
| 手淘/入淘 Tab | 入淘交付、Tab 改版、轻应用等 |
| 用户产品与用增 | 会员、CRM、群聊、评价、支微多端等 |
| AI 产品/问一问 | AI Agent、拍照讲解、厂商合作等 |
| 生产端 AI 赋能 | AI 会场搭建、途灵生图、生成式 UI 等 |
| 各行业端侧进展 | 交通、酒店、度假、商旅、保险等各域 |
| 基建和性能保障 | 脚手架、容器、包大小、鸿蒙适配等 |
| 团队建设 | 绩效、盘点、技术分享等（整体视角，不罗列小团队各自事项） |
| **AI 工程实践**（**固定放在最后**） | 本月 AI 工具链使用、AI 辅助开发、前沿技术探索与落地 |

### 行文要则

| 原则 | 不要 | 要 |
|------|------|------|
| **带时间** | "项目完成 spec 改造" | "本月开始速推 spec 文档化，截止本月底完成所有客户端工程新项目的 spec 改造" |
| **带范围** | "完成 spec 改造" | "完成所有客户端工程新项目的 spec 改造" |
| **先介绍再讲进展** | "途灵生图平台：第一...，第二..." | "途灵生图平台：我们的多媒体 AI 生成平台本月有了大量新功能优化，第一...，第二..." |
| **完整上下文** | "AI 线路规划 4.9 发布" | "特价机票基于地图交互的 AI 线路规划 4.9 发布，为用户完成线路规划和特价出行方案的组合推荐" |
| **数据准确** | "性能大幅提升" | "秒开率从 44.99% 提升至 47.86%，提升 2.88PT" |
| **风险说完整** | "存在一定风险" | "存在人力风险，需要从行业协调部分人力支持" |

### 去 AI 味

- **不用**套话："值得注意的是""值得一提的是""总的来说"
- **不用**空泛动词："积极推进""深入探索""全面赋能"
- **不用**连接词堆砌："首先...其次...最后"
- **不加**总结性段落或"展望未来"类收尾
- **直接陈述事实**：做了什么、数据多少、下一步是什么
- **像人写的**，不像 AI 生成的——简洁、直接、有信息密度

### 正交枚举原则

列表中每一项聚焦一个独立的方面或子事项：

- **正交不重叠**：同一板块下的列表项之间不应描述同一件事的不同表述
- **一事多面**：如果一个重点事项有多个方面（架构设计、数据表现、风险点、后续计划），拆成多条
- **颗粒度**：每条约 1-3 句话，包含具体数据、状态、时间节点

### 正确写法示例

```
一）双十一和营销大促会场

1. 双十一会场，10.15 上线预热，10.20 上线正式，全端秒开率 90.4%，端内 95.1%，日均 UV 43.9w，转化率 7.7%。
2. 爆款榜单，市场部今年重用，针对性做了微信 H5 二次分享卡片、分享口令复制、钉钉分享唤端等优化。
3. 行业侧双十一需求进展：
   1. 交通：宝贝链路支持海外版淘宝，1111 前发布一单链路。
   2. 酒店：套餐双十一交付顺利，月底上线切流。

   1. 本月完成端侧双十一链路问题排查，沉淀了端侧双十保障手册。
   2. 直播性能：李佳琦直播峰值 8402QPS，降级率 4%，对比去年 3300+ 峰值、50% 降级率，提升明显。
```

### 错误写法示例

```
一）双十一和营销大促会场

双十一期间各团队全力保障，完成了会场搭建和性能优化。双十一会场 10.20 上线，秒开率 90.4%，UV 43.9w。各行业也完成了各自需求交付，交通支持了海外版淘宝，酒店支持了套餐双十一。
```

## 模板 31：团队新年祝福（个人化寄语）

适用场景：年末或年初，TL 给团队每个成员写一段个性化的新年祝福/寄语。这不是群发的模板消息，是**给每个人的定制化祝福**——让每个人都感受到"老大认识我、了解我、在意我"。

### 写作原则

1. **一人一段，绝不群发**：每个人都值得专属的几句话。如果写了半天发现对谁都适用，说明不够个性化。
2. **观察驱动，不是祝福驱动**：核心不是"新年快乐万事如意"，而是"我注意到你这一年发生了什么"。先说你对 TA 的观察，再送祝福。
3. **回忆具体瞬间**：最好能提到一个具体的事件、一个成长节点、一个让你印象深刻的细节。
4. **有温度但不油腻**：真诚、轻松、偶尔幽默。不要上升到"价值观高度"，不要写"感谢你对公司的贡献"这种话。
5. **结尾要有劲**：用"加油"、"看好你"、"值得期待"等短句收尾，有力量感。
6. **适当引用时代梗**：当年流行的电影、网络梗、团队内部的共同记忆，都可以作为素材，让祝福有时代感和归属感。

### 祝福结构

```
{称呼}

{第一段：回顾 TA 的这一年}
- 可以是 TA 经历的变化（入职、转正、角色转变）
- 可以是 TA 带给团队的东西（快乐、温暖、专业）
- 可以是一个具体的事件或成长瞬间
- 用"过山车"、"收获"、"成长"等关键词串联

{第二段：展望新年 + 鼓励}
- "属于你的 20XX"、"我对你充满期待"、"看好你"
- 如果 TA 这一年有遗憾或不完美，轻巧地化解（"不纠结"、"拾起久违的激情"）
- 以"加油"收尾

{可选的第三段：个人关怀}
- 生活中的小叮嘱（"少抽点烟"、"多买彩票"）
- 或一个团队共同记忆的梗（"没船票也照样活得精彩"）
```

| 反模式 | 示例 | 修正 |

| **群发模板** | "祝你新年快乐，工作顺利，万事如意" | 至少提到一个 TA 这一年的具体经历或特征 |
