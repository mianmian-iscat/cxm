## 模板 13：项目 KO 文档

适用场景： 启动一个战役型或跨团队大型项目，需要正式的 Kickoff 文档。

```markdown
# {项目名称} Kickoff

## 一、背景与问题

**痛点陈述**：{用一句话描述当前最核心的问题/阵痛}

**战略关联**：{本项目与组织战略的连接点}

**集体决策**：{为什么是现在、为什么是这个方向}

## 二、双重使命

| 使命 | 描述 | 衡量标准 |
|------|------|----------|
| 用户/业务使命 | {面向用户/业务的交付} | {可量化的业务指标} |
| 技术/基建使命 | {借机推进的技术基建} | {可量化的技术指标} |

## 三、子项目拆解

| # | 子项目 | 技术 PM | 关键交付 | 里程碑 |
|---|--------|---------|----------|--------|
| 1 | {子项目名称} | {姓名} | {核心交付物} | {时间节点} |
| 2 | | | | |
| ... | | | | |

## 四、组织保障

- **大 PD（产品负责人）**：{姓名}
- **大 PM（技术负责人）**：{姓名}
- **后备 PM**：{姓名}
- **集中办公安排**：{时间、地点}
- **项目管理工具**：{Aone 项目集链接}

## 五、沟通节奏

| 频率 | 形式 | 参与人 | 内容 |
|------|------|--------|------|
| 每日 | 站会 | 各子项目 PM | 进展、阻塞、依赖 |
| 每周 | 周报 | 全组 | 运营报告（进展/风险/问题/决策） |
| 里程碑 | 汇报 | 管理层 | 阶段性成果、下阶段计划 |

## 六、战略意义

{2-3 句话，将本项目从"任务"提升为"使命"}
```

## 模板 19：原声观点（Original Voice Viewpoint）

适用场景： 需要以第一人称写一篇关于某话题的个人观点文章（如团队内部分享、ATA 文章、对新人的忠告）。不是操作框架，是"我是怎么想的、为什么这么想"。

### 写作结构

```markdown
# {话题}

{一句话开场：点明你为什么有资格/有动力谈这个话题}

## 定义你要说的事

{先用 1-2 段把核心概念说清楚。用你自己的话，不要引用教科书。}

例："我们开始大量招人了。目前我们招的是有潜力的 P5，那么，什么是有潜力的 P5？"

## 展开你的判断框架

{把你的判断拆成可操作的维度。不要抽象地说"综合素质好"，要拆到面试时能问什么、看什么信号。}

{维度可以来自 JobModel、也可以来自你自己的观察框架。关键是要有"我在面试时怎么判断"的具体方法。}

## 人的成长阶段（如果适用）

{如果话题涉及人的成长，按时间线描述不同阶段的特征。每个阶段说清楚：这个阶段的人通常在做什么、能力边界在哪里、怎么判断 TA 是不是在往下一阶段走。}

## 你的面试/实践方法

{分享你实际怎么做的。不要讲理论，讲"我面试时习惯怎么准备问题、怎么设 S 和 T、怎么让面试者回答 A 和 R"。}

{列出你常用的几类问题，每类问题说明你要考察什么、怎么判断回答质量。}

## 收尾（你的态度）

{用一句体现你个人风格的话收尾。不要总结陈词，不要喊口号。}

例："总之，如果聊的 happy，掌握一些技巧和门路，是能对面试者有比较客观的评价的。"
```

### 写作原则

- **第一人称**：始终是"我认为"、"我的习惯是"、"我会怎么判断"
- **具体到可操作**：每个判断维度都要有"面试时问什么、怎么判断"的落地
- **允许不完美**：不是学术论文，不需要穷举。"以上是我的一些面试心得体会，希望大家拍砖"这种语气就对了
- **有案例**：举一个"这类人会怎样、那类人会怎样"的对比，让读者能代入
- **有态度**：不是中立综述，是你的观点。"偏科严重的人直接锯掉"——敢下判断

### 范例结构（来自"神码是有潜力的P5"）

> 原文结构：定义概念 → 按工作年限分四个阶段描述人的成长 → 每个阶段的判断标准和淘汰条件 → 面试实操方法（6 类问题）→ 个人态度收尾

> 关键技巧：把 JM 中的抽象描述翻译成面试官能操作的具体问题。"来了能干活"→ 问"切页面需要多少时间？哪些地方需要注意？有无风险？"如果回答"时间不一定"，说明技能不过关。

## 模板 20：叙事型面试评价

适用场景： 完成一次面试后，需要写一份完整的面试评价记录（区别于模板 16 的结构化表格，这个模板更接近真实面试的叙事流）。适用于需要详细记录面试过程、供后续面试官或 HR 参考的场景。

```markdown
# {候选人代号} 面试评价

**面试日期**：{date}  **面试官**：{name}  **目标层级**：P{X}~P{X+}

## 候选人背景

{2-3 句话：毕业时间、专业背景、第一份工作选择的原因（如果聊到了的话）。这部分帮助后续面试官快速建立对候选人的第一印象。}

例：2015 年通信专业毕业，毕业后花了一些时间考虑工作城市，10 月份入职第一家公司。

## 职业经历（按时间线）

{按时间顺序记录候选人的主要工作经历。每段经历记录：}
- **在什么公司/什么业务线**
- **做了什么核心工作**
- **遇到了什么变化/挑战**（公司层面的变动、项目被砍、团队调整等——这些往往是面试中最有价值的信息）
- **候选人在变化中的表现**（是被动接受还是主动应对）

{重点关注：}
- **从零到一的经历**：有没有独立搭建过什么？基建工程能力怎么样？
- **技术沉淀的延续性**：前一段工作积累的能力有没有带到下一段？
- **主动推动的事**：有没有主动发现问题并推动改进的经历？

## 关键项目深挖

{选 1-2 个最有代表性的项目深入记录。}

**项目 1：{项目名/方向}**
- 背景：{为什么做这个}
- 候选人角色：{做了什么}
- 技术挑战：{难点在哪}
- 候选人的应对：{怎么解决的}
- 成果：{带来了什么价值}

## 候选人关心的事

{记录候选人主动提出的问题。候选人关心什么，往往说明 TA 在意什么、经历过什么。}

- {关心的问题 1}
- {关心的问题 2}

## 薪资信息（如需记录）

- 当前薪资：{脱敏}
- 期望涨幅：{X}%

## 总体评价

{用一段话总结候选人的整体画像。不是列表，是叙事——把几个关键特质串起来，形成一个人的完整形象。}

{要包含的维度：}
- **专业基础**：扎实程度、架构设计思路
- **做事风格**：沟通主动性、投入度、情绪管理
- **独特价值**：这个人和别人比，最突出的特质是什么
- **延续性**：在变化频繁的环境中，技术积累有没有延续

## 不足与风险

{诚实指出不足，但区分"硬伤"和"可通过时间弥补的短板"。}

- **不足 1**：{描述} — {是硬伤还是可弥补？}
- **不足 2**：{描述} — {影响程度}

## 判断

- **建议层级**：P{X} / P{X+}
- **是否推荐**：{推荐 / 待定 / 不推荐}
- **建议 HR 重点考查**：{如适用，指出 HR 面试应重点关注的维度}
- **与岗位的匹配度**：{候选人最 match 的方向/最需要注意的方向}
```

### 写作原则

- **叙事而非填表**：不是打分表，是把面试中观察到的信息串成一个人的故事
- **区分事实和判断**：候选人说了什么是事实，"我觉得 TA 专业基础扎实"是判断，要分开写
- **记录变化中的表现**：候选人在公司裁员/项目被砍/团队调整时的反应，比顺境时的表现更有判断价值
- **不足要分硬伤和短板**：硬伤（如偏科严重、沟通障碍）影响录用决策，短板（如某方向经验少）可能通过时间弥补
- **脱敏**：公司名、具体薪资数字、人名等敏感信息应脱敏处理

### 范例一：P6+ 社招面试评价

> **背景段**：记录毕业时间、Gap 原因、第一份工作选择。不评价，只记录。
>
> **职业经历段**：按时间线，每段记录"做了什么 → 遇到什么变化 → 怎么应对"。重点标记：从零到一的项目（"基本上做到了零到壹的初期建设和封装"）、技术沉淀的延续（"小剪的很多基建能力被延续了下来"）、主动推动的事（"拉着各个角色落地了中台素材管理库"）。
>
> **总体评价段**：一段话串起几个关键特质——"专业基础知识扎实"、"兼顾 iOS 和 Android 的通用性和 API 一致性"、"情绪管理比较好"、"做事投入度很高"。
>
> **不足段**：诚实但公平——"经验稍微单一一些，多是视频剪辑方面"——然后判断"不是什么硬伤"。
>
> **判断段**：给出明确层级建议（P6+），并给 HR 面试提示（"建议重点考查抗压能力"）。

### 面试评价原文（范例一）

某P6+候选人的面试评价：

2015 年通信专业毕业，8月份毕业后没有立即找工作，当时纠结工作地，不太想留在西安，花了一些时间转了几个大城市，最终 10 月份的时候决定找工作，入职了第一家公司，所以毕业到第一家公司之间有三四个月的Gap。

在网易这边的工作变更比较频繁，最近产品线一直在陆续裁撤，候选人6 月份已经离职，这次看新机会的原因主要就是业务收缩裁员，下一家公司希望能更稳定一些。六月份离职后刚好二阳了，就开始健身恢复了一下身体，七月份之后恢复体重，基本上是上周开始找工作。

### 范例二：校招实习生面试评价（推荐信式）

适用场景：你带过的实习生参加校招面试，你作为推荐人/面试官写一份评价。这种评价的目的不只是记录，更是**帮助候选人在后续面试（特别是 HR 终面）中建立可信的正面形象**。

#### 推荐信式评价的核心手法

**为什么"坦诚风险"比"全是好话"更有效？**

HR 面试官看到的推荐信大多是清一色的好话。一份"全是优点"的评价反而让人怀疑——要么面试官不了解候选人，要么在刻意包装。反过来，一份敢说"这个人有脾气、需要引导"的评价，因为诚实而获得可信度，HR 会更愿意相信你说的优点也是真的。

**推荐信式评价的四个层次：**

1. **技术背书用事实** — 不是"技术很好"，而是"大三实习期间对航旅前端技术架构非常了解"、"进步非常大"。用你的直接观察（而非面试中的短暂接触）来背书。
2. **性格画像用故事** — 不是"性格开朗"，而是"语出惊人、经常挑战权威"、"在知乎和微博上有一定人气"。给 HR 一个立体的人，而不是一个标签。
3. **风险预警给解药** — 不是"需要注意"，而是"需要一个强势的主管或师兄来带"、"弄不好就会有负面影响"。承认风险的同时给出管理方案，让 HR 觉得"这个风险是可控的"。
4. **给 HR 面试的导航** — 明确告诉 HR 该重点考察什么："留心他参加阿里面试的动机、重点考察他的稳定性"。这既帮了 HR，也帮了候选人——HR 带着正确的问题去面试，而不是带着疑虑。

#### 面试评价原文

张三大三的时候就在我团队实习（航旅前端团队），表现非常突出，前端技能全面扎实，而且对航旅前端技术架构非常了解，文字表达能力极强，有一定设计美感，特别注重交互体验，有交互设计的功底，人比较聪明。抗压能力也ok。大三这一年实习期间的进步非常大，对于一个大三的同学已然非常难得。后来希望多充实一下自己的实习经历，选择离开去微信电影票实习，也是做前端（微信电影票业务的前端Leader也是我们的前同事）。

技术上基本同意初面的评价，达到A。

关于人的性格方面，因为年龄很小，所以经常语出惊人，也经常挑战权威，这一点非常棒（我个人表示非常欣赏），但需要主管很仔细的引导，弄不好就会有负面影响，张三对业务中很多脏乱差的现象多少有些抱怨（和质疑），而且这些声音会不自觉的传达出来，个人在知乎和微博上也有一定的人气，我在带他期间，开始担心的是他把一些公司内（不好）的状况到外面公开出去，实习阶段下来他的表现还算比较克制，口头可能会有微词，行动上还是能照顾到大团的利益。因此需要一个强势的主管或师兄来带他，这样他的成长速度会非常快，要注意合理的引导。这种性格不是所有人都能适应，而且这种自信很容易被人理解为自负。并二面和HR面试需要仔细辨别，并留心他参加阿里面试的动机、重点考察他的稳定性。我个人推荐层级为A。

#### 为什么这份评价能通过 HR 终面

| 手法 | 原文体现 | 效果 |
|------|---------|------|
| **用直接观察背书** | "大三就在我团队实习"、"实习期间的进步非常大" | 你不是面试了一次，你带了他一年——这个背书权重远高于一次性面试 |
| **技术判断明确** | "技术上基本同意初面的评价，达到A" | 不模棱两可，直接给等级 |
| **性格立体不包装** | "语出惊人"、"挑战权威"、"抱怨和质疑" | HR 读到这里会觉得：这个面试官是真诚的，不是在做推荐任务 |
| **风险有解药** | "需要一个强势的主管或师兄来带他" | 不是说"没问题"，而是说"我知道怎么管他"——风险变得可控 |
| **口头 vs 行动的区分** | "口头可能会有微词，行动上还是能照顾到大团的利益" | 这个区分极其关键——告诉 HR：他的"刺"停留在表达层面，不影响执行 |
| **给 HR 导航** | "留心面试动机、重点考察稳定性" | 帮 HR 聚焦到正确的考察维度，减少因误判而否决的概率 |
| **推荐等级明确** | "我个人推荐层级为A" | 不含糊，有立场 |

#### 校招/实习生评价与社招评价的差异

| 维度 | 社招（范例一） | 校招/实习生（范例二） |
|------|-------------|-------------------|
| **信息来源** | 一次面试中的对话 | 长期实习中的直接观察 |
| **技术评价** | 从项目深挖中推断能力 | 从日常工作产出中直接判断 |
| **性格评估权重** | 较低（主要看专业能力） | 较高（校招看潜力，性格是潜力的核心指标） |
| **对 HR 的指引** | 简单一句"建议重点考查 X" | 详细的风险说明 + 管理方案 + 考察维度 |
| **评价者的角色** | 中立的面试官 | 有立场的推荐人（"我个人表示非常欣赏"） |
| **说服策略** | 客观呈现让读者自己判断 | 坦诚风险 = 可信度 → 优点更被采信 |
