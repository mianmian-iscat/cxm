# P9 Skill 测试用例

这个目录存放 `p9` skill 的维护性测试材料。测试目标不是检查参考材料全文，而是验证 skill 在典型输入下是否能做出正确路由、遵守关键行为约束，并保持目标行文风格。

## 测试范围

- `routing-cases.yaml`：验证用户意图到 reference 组合的路由是否合理。
- `behavior-cases.yaml`：验证事实、判断、价值选择、AI 口径等关键行为。
- `style-cases.yaml`：验证输出风格，避免官样文章、角色扮演和未脱敏信息。
- `static-checks.md`：人工或脚本化静态检查清单。

## 使用方式

每次修改 `SKILL.md` 的路由、观点使用规则、风格约束，或修改 AI 相关参考材料后，至少抽样跑一遍对应 case。

检查时不要要求输出逐字一致，只看以下三类结果：

1. 是否读取或引用了期望的参考材料。
2. 是否覆盖了 `must_cover` 中的关键判断。
3. 是否避开了 `must_not_include`、`must_not_route_to` 和反模式。

## 维护原则

- 测试 case 只描述期望行为，不复制大段 reference 原文。
- 新增场景时优先补 case，再改路由。
- 当一个 case 同时测多个目标时，拆成多个 case。
- 测试目录不属于运行时材料，不要从 `SKILL.md` 链接为默认参考材料。
