# P9 Skill 静态检查清单

修改 `p9` skill 后，至少执行以下检查。

## 链接检查

- `SKILL.md` 中的相对链接必须存在。
- `references/` 内 markdown 文件之间的相对链接必须存在。
- 指向兄弟 skill 的链接必须从 `skills/p9/` 或 `skills/p9/references/` 的实际相对路径出发检查。
- 不允许保留已确认失效的 `references/references/...` 或错误层级链接。

## 路由检查

- 专用 skill 优先：OKR、月报、晋升评审不要被 P9 泛化路由抢走。
- 主领域单选：同一个输入不要因为关键词同时加载多个大类。
- AI 四类场景互斥：方案判断、趋势判断、个人应对、团队转型规划只能选一个主路由。
- “跨团队 / 大型战役”是项目管理修饰条件，不是独立主领域。
- “复盘”泛化场景不能覆盖“项目结项复盘”的精确路由。
- “个人晋升准备”和“晋升评审他人”必须分开。

## 三任务编排检查

- 中型及以上任务的第一个任务管理动作必须初始化接、化、发三阶段任务；Claude Code 用 `TaskCreate`，Codex 用 `update_plan`。
- 入口判定只能内心粗判，不输出任务规模、路由原因、命中文件或协议解释；三阶段任务初始化前如需可见文本，最多一句固定弱提示：“按执行协议，先创建三阶段任务。”
- `SKILL.md` 必须显式声明每次激活 `p9` 处理实质性任务都要读取 `references/task-rules.md`，它是强制加载的执行协议，不是可选参考。
- `SKILL.md` 必须保留不可延迟动作：入口判定为中型及以上后，先用当前宿主任务工具恰好创建接、化、发，再将接置为 `in_progress` 并输出一句弱反馈，然后读取 `references/task-rules.md`。
- 未读取 `references/task-rules.md` 前，不得进入化阶段、不得读取业务 reference、不得输出判断摘要。
- 不到中型的任务不初始化三阶段任务，但入口判定后仍必须先读取 `references/task-rules.md`，再执行接阶段。
- `SKILL.md` 必须内联保留终止硬门禁：最终正文和收口句后同一次响应尾部只能执行关闭动作；Claude Code 为 `TaskUpdate completed` + `TaskComplete`，Codex 为 `update_plan` 将「发」置为 `completed`，关闭后不得输出任何文本。
- 三阶段初始化恰好创建 3 个任务：接、化、发；不要创建一个总任务、停在 2 个任务、追加第 4 个“结束任务”或更多任务。
- 第三个任务标题必须是“发 — 输出主体 + 一句话收口 + 关闭任务”，关闭任务职责属于发阶段正文同一次响应尾部的纯工具关闭调用。
- 精确路由和读取 reference 必须发生在三阶段任务初始化之后。
- 接、化、发每个阶段开始必须将该阶段置为 `in_progress`，完成必须置为 `completed`；Claude Code 用 `TaskUpdate`，Codex 用 `update_plan`。
- 接任务 `in_progress` 后、读取 reference 前，必须输出一句弱进度提示；但不能输出路由推导、文件清单、模板名或来源说明。
- 化任务 `in_progress` 后必须输出简短判断摘要；“零旁白”不是零输出，不能跳过问题分解和主要取舍说明。
- 化阶段判断摘要输出后，必须先完成「化」，再开始「发」，不得把化摘要和发正文合并在同一个响应中。
- 发阶段完成标志是主体交付物已输出、收口句已输出、且不再需要工具调用改变内容；如果仍需要工具调用补充材料、验证事实或修改输出，保持发任务 `in_progress`。
- 指令型任务必须在发阶段完成所有实际动作：读取材料、修改文件、保存产物、运行验证、提交评论、整理最终回复草稿；只要还有待执行动作、待验证结果或待用户确认分支，就不能完成发任务或调用 `TaskComplete`。
- 发阶段承担可见长正文输出；不要为了提高完结率在最终正文输出前提前完成发任务。
- 发阶段只能输出一次主体正文；第一次主体正文开始输出后，本轮交付进入不可重写路径，不能生成第二版、替代版、补充版或更完整版本。
- 最终正文和收口句输出前，发任务必须保持 `in_progress`；禁止在正文输出前完成发任务或调用 `TaskComplete`。
- 发阶段零旁白，只输出一次最终正文；不要输出读取过的文件、使用过的模板、素材来源、输出生成过程、“来源标注/参考资料/依据材料”附录或“下次可以”之类的复盘说明。
- 问题型 prompt 的正文收口句之后，不能追加二次总结、复述用户问题、回放“核心结论/刚才的策略”、追问用户背景或邀请继续补充信息。
- 收口句全轮最多出现一次；`TaskComplete` 后不能重复、改写或补发收口句，也不能输出”任务已完成”等弱提示。如果平台强制生成 tool 后 assistant 消息，消息体必须为空白，不能输出任何可见文字。
- `TaskComplete` 后如果平台或 harness 生成了新的 assistant turn，该 turn 不得重新回答用户问题、重新分析上下文或输出任何实质性内容——消息体必须为空白。”关闭后再来一轮”是严重违规。
- 最终正文和收口句输出后，同一次响应尾部必须只携带关闭工具调用：完成发任务，调用 `TaskComplete`；如果当前环境没有 `TaskComplete`，则以发任务 `completed` 作为结束动作。Codex 没有 `TaskComplete` 时，`update_plan` 将「发」置为 `completed` 就是终止动作。
- 纯工具关闭必须发生在最终正文所在响应的尾部；长正文输出那次响应先负责正文和 `> 📌` 收口句，随后只负责关闭「发」并调用 `TaskComplete`。
- 关闭调用禁止任何自然语言：不要解释、不要补充、不要总结、不要重复收口句、不要说“任务已完成”，只调用关闭任务工具。
- 收口句（`> 📌`）和关闭工具调用（`TaskUpdate completed` + `TaskComplete`）之间不得插入任何非关闭工具调用——不 Bash、不 Read、不 Glob、不 Grep、不 Write、不 Edit、不列目录、不跑命令、不扫描环境、不验证事实。所有实际动作必须在收口句之前完成。
- 收口句使用 `> 📌` 格式（blockquote + 📌 emoji），全轮最多出现一次，是最后一段可见正文。
- 第一个 `> 📌` 是终止哨兵；出现后只允许关闭「发」并调用 `TaskComplete`，不得继续分析、重写正文、补发另一版答案或为了 final response 输出任何文字。
- 纯工具关闭调用不能输出任何可见文本；只能执行 `TaskUpdate status=completed` 和 `TaskComplete`。
- 纯工具关闭是不可逆终止门，不是继续执行阶段；`TaskComplete` 后不能再读取文件、修改文件、运行测试、补充证据、修正文案、推动新的任务动作或发送可见文本。
- 不能输出长正文后自然停止，留下发任务未完成或未调用 `TaskComplete`。
- 需要 ≥1 个 reference 的任务至少是中型，不能因为只命中一个主 reference 就降级为小型。
- typo、单句改写、简单事实、无需 reference 的小改动不初始化三阶段任务。
- 所有规模任务默认不在化阶段暂停；只有用户明确要求、关键信息缺失会跑偏、高风险不可逆判断、或明显改写目标/范围/交付对象时才暂停确认。
- 规划、方案、行动计划、分析建议类任务必须继续进入发阶段，不能停在“方向是否对齐？”，不因规模大小改变。
- 如果化阶段明显改写用户目标、范围或交付对象，必须暂停确认，并询问用户是否按改写后的目标继续，不能静默替用户换题。
- 挑战用户前提、翻译口号、调整结构不等于目标重写，不能因此自动暂停。
- 收口句必须按 prompt 类型收束：问问题的呼应开头问题，下指令的总结已完成交付；不得另加标题或在收口句后补充说明。
- 完成「发」必须通过 `TaskUpdate status=completed`，不能只在文字里声明完成。

## 数据口径检查

- AI 数据材料必须明确时间口径：2026 年 6 月。
- 仓库扫描数据优先使用比例表达，不强依赖活跃仓库绝对分母。
- 面向用户输出 AI 工程化数据时，优先使用时间口径 + 阈值/区间表达，不默认复述会过期的精确扫描点数。
- AI 转型数据默认按“阿里集团平均水平 / 集团平均水位”表述；除非用户素材明确要求特定 BU，不要说“飞猪当前”。
- 成熟度分布使用粗粒度比例，不输出小数点：`54.8%` → “接近 55%”，`31%` → “约 30%”，`91.3%` → “九成左右”。
- CI/CD 和测试文件覆盖的默认表达是“当前（2026 年年中）CI/CD 配置覆盖率不到 1%，有效测试文件覆盖率不超过 15%”。
- 不要求解释覆盖率定义。
- 不纠结未生成报告仓库，不把个别缺失报告写成影响结论的大问题。
- 效率提升类数字如无严格测量方法，应表达为阶段观察、经验目标或区间判断。

## 风格检查

- 不出现未脱敏的具体人名、花名或可识别个人信息。
- 不出现资历压人表达，如“作为 P9”“作为阿里资深专家”“我有 15 年经验”。
- 不把“参照材料作者风格”写成角色扮演。
- 不强制第一人称输出，按任务自然选择人称。
- 禁用空洞管理词：赋能、打造、引领、深耕、拉通。
- “闭环”仅在 AI 材料中的知识闭环、验证闭环、上下游闭环语境下保留；其他场景改成具体动作和结果。

## 输出质量检查

- 结论先行。
- 区分事实、判断和假设。
- 价值选择尊重用户，但事实声明要核验口径。
- 判断和方案结论可以挑战，不能为了迎合用户包装弱结论。
- 涉及行动计划时必须包含负责人、依赖、关键路径和验证标准。
- 小任务按小任务处理，不启动完整战略判断。
