# 原创保护-已知问题与踩坑

本文沉淀历史排查中发现的疑难问题、不可靠链路和测试盲区。新版本回归时优先覆盖这些场景。

## 1. 数据层问题

### 1.1 DB 实际名称与别名不一致
- 现象：DMS 查询用 `--db scenario` 报"数据库不存在"
- 原因：scenario 是别名，实际 DB 名是 `prod`
- 修复：`dms-alibaba sql query --db prod --sql "..."`

### 1.2 yc_right_apply 状态字段语义
- 现象：UI 显示"已转正"但 to_regular_status 字段为空
- 原因：状态判断不仅看 to_regular_status，还需联合 first_launch_status 等字段
- 排查：查 yc_right_op_log 操作历史还原状态机

### 1.3 跨表 JOIN 性能
- 现象：yc_tort_record JOIN yc_right_apply 查询超时
- 原因：tort_record 量大但缺索引
- 修复：加 id 范围限制 `WHERE yt.id BETWEEN X AND Y`（参考 F88 经验）

## 2. 消息链路问题

### 2.1 MetaQ 重复消费
- 现象：同一 right_id 创建多个 yc_right_settle_order
- 原因：Consumer 未做幂等
- 修复：用 `INSERT IGNORE` 或唯一索引 `(right_id, stage)`

### 2.2 死信积压未告警
- 现象：%DLQ%TOPIC_YC_SETTLE 积压 200+ 但小二端无感知
- 原因：死信不会重投，缺失监控
- 测试：制造消费失败 → 验证死信告警是否触发

### 2.3 顺序消息乱序
- 现象：首发标先摘除再打上（逻辑反向）
- 原因：Tag 不同导致非顺序消费
- 修复：同业务用同一 Tag + ShardingKey

---

## 3. 定时任务问题

### 3.1 任务漏跑
- 现象：某天 SettlementCalcJob（代码类名: ServFinishIncomeJob）未执行，导致结算延迟
- 原因：ScheduleX 故障 + 无补偿机制
- 测试：模拟当日任务失败，验证次日是否补跑

### 3.2 任务跨日数据
- 现象：23:59 提交的补贴申请，次日 09:00 任务未扫到
- 原因：时间窗口判断用 `gmt_create >= 今日 00:00:00`，未包含跨日
- 修复：用 dataTime 参数明确指定处理日期

### 3.3 70% 阈值精度问题
- 现象：69.999% 被判定为达成 70%
- 原因：浮点数比较未用 BigDecimal
- 修复：所有金额/比例字段用 BigDecimal + setScale

## 4. 状态机问题

### 4.1 to_regular_status 编辑性混淆
- 已沉淀MEMORY：是否首发的可编辑性由业务生命周期控制，非 to_regular_status 直接决定
- 测试要点：to_regular_status 非空时下拉框禁用

### 4.2 状态非法跳转
- 现象：已结算订单可以回退到"待结算"
- 原因：前端未做状态机校验
- 修复：前端 + 后端双重状态机校验

### 4.3 状态文案不一致
- 已沉淀F88 MEMORY：F88 是"确认/丢弃"非"通过/不通过"
- 类比原创保护：UI 文案需与产品文档严格对齐

### 4.4 转普通申请 UI 文案不一致 [需求#83163231]

**现象**: 商家端"提交普通申请"按钮的 tooltip 文案和二次确认弹窗文案与 PRD 存在差异。

**已知缺陷**:
- Bug 83290119: Tooltip 文案6处差异（"瞳约效果"应为"侵权打击效果"、"专利证书下发"应为"未下发专利证书"等），已修复
- Bug 83290135: Modal.confirm 弹窗文案差异（"将不享受"应为"暂不享受"、缺少"申请后将扣除服务次数"），已修复

**源码位置**: `src/components/PatentDetail/components/StatusTimeline/index.tsx`
- Tooltip: 组件内 `<Tooltip title="...">` 属性
- Modal: 第467行 `Modal.confirm` 的 content 属性

**正确文案**:
- Tooltip: "国知局受理（预计1工作日）后可发布商品，普通国知局专利申请周期预计在8-10个月，确权周期内将为您进行维权，但因未下发专利证书可能影响侵权打击效果"
- Modal: "普通申请暂不享受平台补贴，申请后将扣除服务次数，是否确认申请？"

**根因**: Bug 83290119 为预发环境未部署最新代码；Bug 83290135 为代码缺陷，已在 master 分支修复。

## 6. 跨平台维权问题

### 6.1 平台覆盖不全
- 现象：维权后只下架了淘宝，其他平台未触发
- 原因：维权配置未勾选其他平台
- 测试：6 个平台分别验证维权流程

### 6.2 爬虫识别准确率
- 现象：误报正版商品为侵权
- 原因：爬虫规则匹配过宽
- 测试：构造相似但非侵权商品验证

### 6.3 申诉窗口期
- 现象：申诉期内已下架商品
- 修复：申诉中状态保持商品在线

### 7.1 补贴档位错算

## 8. 千牛白名单问题

### 8.1 TTYCBH 白名单未配置
- 现象：商家入驻时提示"抱歉，该服务现面向具备高原创能力要求的商家开放，如有需求您可联系店铺小二申请加入"
- 根因：`SellerEnterDomainServiceImpl.enter()` 调用 `qnTagReadFacade.hasUserDataTag(sellerId, "TTYCBH")` 校验商家是否拥有千牛标 `TTYCBH`（原创保护商家准入千牛标），不通过则抛 BizException 拦截入驻
- 代码位置：`taobao-yc-serverless-domain/.../domain/service/impl/SellerEnterDomainServiceImpl.java:65-67`
- 实现链路：`QnTagReadFacadeImpl` → `QnResourceTagService.hasResourceTag(userId, qnTagCode, projectName)` → 千牛平台侧标签服务
- **千牛标管理入口**：https://qn.alibaba-inc.com/qndev-data-app/management#/
- 修复/绕过：在千牛标管理后台给目标 sellerId 打上 `TTYCBH` 标签即可通过入驻校验
- 注意：代码中注入了 `YcSellerWhitelistConfig` 和 `YcCommonConfig(isTestSeller)`，但当前 enter() 方法的白名单校验未使用这两个 config 做 bypass，预发与生产走同一套千牛标校验逻辑

#### 打标 SOP（标准操作流程）

**触发条件**：用户/测试账号遇到"抱歉，该服务现面向具备高原创能力要求的商家开放，如有需求您可联系店铺小二申请加入"提示时，引导用户打千牛标。

**操作步骤**：
1. 跳转千牛标管理后台：https://qn.alibaba-inc.com/qndev-data-app/management#/
2. 点击「名单管理」
3. 选择「名单操作 = 打标」
4. 选择「名单操作 = 上传TXT」
5. 上传 sellerId TXT 文件

**文件格式规范**：参考 https://alidocs.dingtalk.com/i/nodes/XPwkYGxZV347LdvpH6ZEyr1xJAgozOKL?utm_scene=team_space

正确格式示例（每行一个纯数字sellerId，无多余字符）：
```
2213249110271
2219635657158
```

**常见错误场景与解决方案**：

| 场景 | 错误示例 | 解决方案 |
|------|---------|---------|
| 场景一：文档格式有问题 | 非TXT格式或编码错误 | 使用官方提供的 `可使用的文档.txt` 模板 |
| 场景二：文件名单存在科学计数法 | `2.21925E+12` | 导出名单前确保 Excel 单元格格式为「纯文本」，再复制到TXT |
| 场景三：单个ID数字后面有空格 | `2219635657158 `（末尾空格） | 删除每行末尾空格 |
| 场景四：每个ID后面有逗号 | `2213249110271,`<br>`2219635657158,` | 删除每行末尾逗号，使用换行分隔 |
| 场景五：文档中有非数字信息 | `2219635657158 // 测试账号`<br>`商家A: 2213249110271` | 删除中文备注、注释、冒号等非数字信息，每行只保留纯数字sellerId |

**千牛标 Code**：`TTYCBH`（原创保护商家准入千牛标）

**打标成功验证标志**：
- 商家点击「签约」/重新进入服务后，能正常进入「淘天服饰原创保护」商家端首页
- 页面正常展示：专利认证数量、疑似侵权商家数量、4步引导（申请专利→等待专利受理→发布商品→发起维权）、申请列表
- 不再弹出"高原创能力"BizException 提示

**后续可能遇到的二级校验（不同于准入）**：
- 入驻成功后页面右上角可能展示"可用权益数"，权益数=0 时执行新建专利申请等操作会触发 `taobao.industry.yc.right.apply` 的 `BIZ_ERROR::可用权益数不足`
- 处理方式：充值权益 / 换有权益的测试号 / 小二端 cobweb 后台绕过（参考 yc-quick-audit-data-create skill）

## 10. 保护到期日计算问题

### 10.1 保护到期日取早规则
- 规则: min(商品确认一致性后180天, 专利申请日期+1自然年-30天)
- 踩坑: 后端写了接口来修改申请时间以测试不同场景，需注意时间修改后到期日重新计算

### 10.2 无商品确认一致性时间的场景
- 专利申请提交后一直不操作 → 取 专利申请日期+1自然年-30天
- 测试方法: 通过 RightApplyToolHsfService::updateApplyTime 修改申请时间，验证到期日

### 10.3 有商品确认一致性时间的场景
- 确认一致性时间+180天 vs 申请日期+1自然年-30天 → 取早
- 到期日前20天: 发布按钮置灰(publishItemGray:true), 不允许上报线索
- 踩坑: 20天窗口期内既不能发品也不能提交线索，但UI提示不同(按钮灰 vs 文案提示)

### 10.4 20天禁发期边界
```
保护到期日 = 2026-04-11
提交截止日 = 2026-03-22 (到期日-20天)
今日 = 2026-04-01
→ 保护期未结束但不能提交新线索
```

## 11. 草稿态与补充材料问题

### 11.1 草稿不占权益但校验权益
- 保存草稿不占用权益，但**没有权益时不能新建草稿**
- 踩坑: 测试时需确保商家有剩余权益才能创建草稿

### 11.2 补充材料附件展示差异
- 初审阶段: 申请详情和申请表单都展示"查看详细材料"按钮
- 国知局审核阶段: 申请详情展示，**申请表单不展示**
- 踩坑: 国知局阶段去补充时，没有展示文件意见和票条，这是符合产品逻辑的

### 11.3 补充材料格式限制
- 图片: jpg, jpeg, png
- 文档: pdf, doc, docx, xls, xlsx
- 压缩包: zip, rar, 7z, tar, gz
- 国知局补充材料: 只能一个文件展示(doc格式)
- 踩坑: 初审可上传全部格式，国知局有限制

### 11.4 去补充时类目不正确
- 现象: 进入补充材料页面时，产品所属类目显示不正确
- 影响: 可能导致商家补充材料时选择错误类目

## 12. 结算与电子用印问题

### 12.1 服务市场订单限制变更
- 从可多次服务购买改成限制1次服务
- 影响: 存量多个服务次数订单需特殊处理

### 12.2 退款金额校验
- 退款金额必须等于订单剩余全部金额
- 踩坑: 编辑退款金额后提交校验不通过，提示"退款金额必须为订单剩余金额XX元"

### 12.3 补贴回流获取标签失败
- T+4获取标签失败时，延期至T+1重试
- 直到服务期满仍获取不到则按无补贴场景处理

## 13. 童装童鞋业务扩展（需求#83078557）确认事项

### 13.1 类目匹配规则
- 童装/童鞋没有独立一级类目ID，正向测试只验证9类eligible类目
- 非9类判断: 主营类目ID不在 {16,30,50006843,50011740,1625,50010404,50006842,28,50468001} 中
- 类目ID必须精确匹配，不做前缀匹配

### 13.2 签约后变更主营类目场景 [校准 2026-06-30]
- [校准 2026-06-30] 商家签约后**可以**变更主营类目（实测 seller 2213249110271 从 124484008 变更为 50010404）
- 补贴校验取 SYNC_CERT_FILE 时刻的 ODPS 主营类目快照，后续变更不影响已确认申请
- **需要测试**：同一商家跨越主营变更前后的补贴判定差异场景

### 13.3 非9类商家首发标签不可编辑
- UI表现: 直接disabled不可点击，**没有tooltip提示文案**
- 后端API(setRightFirstPublish)也应拒绝非9类商家请求
