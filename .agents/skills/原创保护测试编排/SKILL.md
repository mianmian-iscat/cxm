# 原创保护测试编排

> 本 Skill 是原创保护（淘天服饰原创保护）域的编排层入口，负责把用户的一句话需求拆成 8 个串行阶段并调度对应子 Skill 执行。详细阶段指令见 [references/orchestration-stages.md](references/orchestration-stages.md)。

## 前置声明

任何测试会话开始前，**必须先调用 `att-start`** 登记身份与采证规范，再进入本编排流程。

## 安全红线（不可跳过）

1. **环境限定**：所有 DB 查询必须带 `env = 'staging'`；所有 HSF Tool / MTOP / ScheduleX 操作仅允许预发环境。
2. **HSF Tool env 预检**：任何写操作前必须执行 `SELECT id, env FROM yc_right_apply WHERE id = {applyId}`，仅当返回 `env='staging'` 方可继续；否则立即中止并告警。
3. **禁止 DML**：测试流程中不得执行 UPDATE/DELETE/INSERT；`createDataChangeOrder` 仅在用户显式确认后使用。
4. **生产数据只读**：`env='production'` 数据仅允许 SELECT，严禁任何写入/状态修改。
5. **账号白名单**：默认测试 seller_id 以 `../yc-protection-qa-workbench/test-accounts.md` 为准，当前默认 `2213249110271`。

## 群消息白名单约束

- 仅处理来自以下群/会话的机器人任务：
  - 原创保护测试群
  - F88 / i-FASHION + 原创保护双域 QA 群
  - 机器人测试/联调群
- 非白名单群消息触发时，回复：「请在白名单群（原创保护测试群或双域 QA 群）@我，或私聊发起任务。」
- 私聊任务直接进入编排，不再二次确认群白名单。

## 八阶段速查

| 阶段 | 子 Skill | 核心输出 |
|---|---|---|
| 1. 用例生成 | `原创保护用例生成` | XMind 结构化用例大纲 + pytest 可执行脚本 |
| 2. 规则校验 | `原创保护规则校验` | 规则覆盖清单、状态机缺口、风险项 |
| 3. 数据构造 | `yc-quick-audit-data-create` + `yc-data-factory` | applyId / rightId / settleOrderId，且 `env='staging'` 已确认 |
| 4. 执行助手 | `原创保护执行助手` | API/UI 执行日志、断言结果、截图、traceId |
| 5. 结算/异步验证 | `yc-settlement-analyser` + `yc-data-factory` + `yc-db-verification` | 资金流向分析、Job 链触发结果、结算单子状态验证报告 |
| 6. 缺陷排查 | `yc-defect-diagnosis` | 根因分类、修复建议、Aone Bug 草稿 |
| 7. 测试报告 | `qa-test-report` + `att-report` | 执行报告 + 知识指标报告，钉钉文档 + AOne 回填 |
| 8. 千牛标打标/入驻 | `原创保护千牛标打标` + `yc-data-factory` | TTYCBH 标签已打、`seller_enter_info` 入驻状态 OK |

## 默认跳过条件

| 阶段 | 跳过条件 |
|---|---|
| 1. 用例生成 | 用户已提供现成用例集或 XMind 文件；或明确说「不用生成用例」 |
| 2. 规则校验 | 用户未提及规则/状态机/补贴等业务规则，或已提供规则校验报告 |
| 3. 数据构造 | 用户已提供有效 applyId 且明确无需新数据 |
| 4. 执行助手 | 用户仅要求 DB 验证、结算分析或缺陷排查，无需 UI/API 执行 |
| 5. 结算/异步验证 | 当前需求不涉及结算、退款、确收、补贴、下架率等异步链路 |
| 6. 缺陷排查 | 所有前置阶段结果均为 PASS / 无异常，且用户未提问题现象 |
| 7. 测试报告 | 无 att-tf 执行记录且无手动执行结果可汇总 |
| 8. 千牛标打标/入驻 | 商家已入驻或已打标，且 DB 确认 `seller_enter_info.status` 正常 |

## 执行模式

- **全托管模式**：用户提供 PRD/需求后，按 1→8 自动推进，中间无需确认。
- **单阶段模式**：命中路由规则时只执行入口阶段，不自动进入后续阶段。
- **链式模式**：阶段 N 执行完成后，若其输出是阶段 N+1 的必需输入且用户未显式停止，则自动推进；否则停在当前阶段并输出阶段报告。

## 失败/降级处理

1. 任一阶段返回 FAIL/BLOCKED，优先调用 `qa-self-healing` 进行自愈重试。
2. 自愈无效时，直接进入 **6. 缺陷排查**，输出根因与 Bug 草稿。
3. MCP 不可用时按 L1 重试 → L2 CLI（`dms-alibaba` / `mw hsf`）→ L3 BLOCKED_MCP + IM 私聊用户。
