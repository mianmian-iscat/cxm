# 🔄 校验规则更正说明：模型匹配模式下 seller_id 的必填性

> **更正日期**：2026-07-07  
> **更正原因**：用户澄清了模型匹配模式下 seller_id 的正确校验规则

---

## ❌ 原错误理解

### 模型匹配 × 模板包 / 模板库

```
错误理解：
- seller_id 为可选字段（⚠️ 可选）
- 不填时应匹配全量
- 不强制要求配置
```

---

## ✅ 正确理解

### 模型匹配 × 模板包 / 模板库

```
正确理解：
- seller_id 入参必须有（✅ 入参必传）
- Start 节点必须配置 seller_id
- 后续会根据 seller_id 查询店铺基因
- 但匹配时不会根据 seller_id 去强校验（不是硬匹配）
```

---

## 🎯 关键区别：规则匹配 vs 模型匹配

| 对比项 | 规则匹配 × 模板包 | 模型匹配（模板包/模板库） |
|--------|------------------|------------------------|
| **seller_id 配置** | ✅ 强制必填（硬匹配字段） | ✅ **入参必传**（查询店铺基因） |
| **缺失后果** | 直接报错，无法保存 | 无法查询店铺基因，影响匹配质量 |
| **校验方式** | 强校验（硬匹配） | **弱校验**（不参与强校验） |
| **用途** | 作为硬匹配条件筛选模板 | 查询店铺基因，优化匹配算法 |
| **DOM定位** | 硬匹配字段下拉框 | 无硬匹配字段（模型匹配没有此字段） |

## 🔍 详细解释

### 1️⃣ seller_id 的作用

```
模型匹配模式：
1. Start 节点必须配置 seller_id（入参必传）
2. 运行时根据 seller_id 查询店铺基因
3. 店铺基因用于优化匹配算法（AI模型）
4. 但匹配时不会强制校验 seller_id 是否匹配
   - 不会报错："seller_id 不匹配"
   - 而是优先匹配该商家的模板
```

### 2️⃣ 与规则匹配的区别

```javascript
// 规则匹配 × 模板包（硬匹配）
if (!seller_id_configured) {
  throw new Error("该策略中包括模板匹配，但策略入参中没有商家ID");
}

// 模型匹配（入参必传，但弱校验）
if (!seller_id_configured) {
  throw new Error("Start节点必须配置seller_id");
}
// 运行时
const shopGene = queryShopGene(seller_id); // 查询店铺基因
const matchedTemplates = matchWithAI(shopGene, ...); // AI匹配
// 不会强校验 seller_id 是否与模板匹配
```

### 3️⃣ 实际场景

```
场景：Start 节点未配置 seller_id

规则匹配 × 模板包：
- 点击保存按钮
- 立即报错："该策略中包括模板匹配，但策略入参中没有商家ID"
- 无法保存

模型匹配 × 模板包/模板库：
- 点击保存按钮
- 保存成功（不会报错）
- 但试运行时报错："缺少入参 seller_id"
- 或运行时无法查询店铺基因，影响匹配质量
```

## 🎓 常见错误场景

### 错误场景 1：模型匹配未配置 seller_id

```
操作：
1. 创建策略
2. 添加模板匹配节点
3. 选择"模型匹配"模式
4. Start 节点未配置 seller_id
5. 点击保存

结果：
- 保存成功（不会立即报错）
- 但试运行时提示"缺少入参 seller_id"
- 或运行时无法查询店铺基因，匹配质量下降

正确做法：
1. 配置 Start 节点
2. 新增字段 → 选择 seller_id
3. 保存 Start 节点
4. 再配置模板匹配节点
```

### 错误场景 2：混淆规则匹配和模型匹配的 seller_id

```
错误理解：
- "模型匹配和规则匹配一样，seller_id 都是可选的"
- "模型匹配不需要 seller_id"

正确理解：
- 规则匹配 × 模板包：seller_id 强制必填（硬匹配）
- 规则匹配 × 模板库：seller_id 可选
- 模型匹配（模板包/模板库）：seller_id 入参必传（查询店铺基因）
```
