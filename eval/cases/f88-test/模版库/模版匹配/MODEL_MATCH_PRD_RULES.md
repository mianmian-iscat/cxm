# F88 模板匹配 - 模型匹配PRD规则详解

> **知识库定义**：`knowledge/f88/f88-material-production.json`  
> **核心处理器**：`TemplateMatchProcessor + AI模型`

## 🎯 模型匹配PRD定义

### 知识库中的定义

```json
"模型匹配": {
  "handler": "TemplateMatchProcessor + AI模型",
  "fields": ["模型选择"],
  "sellerRequired": false,
  "note": "由AI算法自动排序，不支持排序维度和硬匹配字段"
}
```

**关键信息**：
1. **处理器**：`TemplateMatchProcessor + AI模型`（在规则匹配基础上增加AI模型）
2. **特有字段**：模型选择
3. **seller_id**：PRD定义为可选（但实际使用中建议配置）
4. **不支持字段**：排序维度、硬匹配字段
5. **核心逻辑**：由AI算法自动排序

## 📊 模型匹配 vs 规则匹配对比

| 对比项 | 规则匹配 | 模型匹配 |
|--------|---------|---------|
| **处理器** | `TemplateMatchProcessor` | `TemplateMatchProcessor + AI模型` |
| **排序方式** | 手动配置（类目>季节>风格>CTR） | AI自动排序 |
| **配置字段** | 排序维度、硬匹配字段 | 模型选择 |
| **seller_id** | 模板包模式必填，模板库模式可选 | PRD定义为可选（但建议配置） |
| **灵活性** | 高（可精确控制） | 低（依赖AI） |
| **匹配质量** | 依赖规则设计 | 依赖AI模型质量 |
| **性能** | 快速（规则计算） | 较慢（AI调用，可能30-60秒） |
| **可解释性** | 高（规则清晰） | 低（黑盒） |
| **适用场景** | 需要精确控制匹配逻辑 | 需要智能化匹配 |

## 🔍 模型匹配PRD规则详解

### 1️⃣ 入参要求

```
必填字段：
- 应用环节（搭配/视觉/套图）
- 应用场景（主图素材/种草素材）
- 模型选择（AI模型）
- 目标匹配数量

可选字段：
- seller_id（PRD定义为可选，但建议配置）
- 疲劳度
```

**seller_id 的作用**：
- ✅ **建议配置**：用于查询店铺基因，优化匹配结果
- ⚠️ **不参与强校验**：不会因seller_id不匹配而报错
- ✅ **影响匹配质量**：有seller_id时优先匹配该商家的模板

---

### 2️⃣ 模型选择

**支持的AI模型**（基于知识库）：

```json
"gen_img": {
  "models": ["wan2.7-image", "wan2.7-image-pro", "gpt-image-2"]
},
"llm_text": {
  "models": ["claude-sonnet-4", "claude-sonnet-4-opus", "qwen3.6-plus"]
}
```

**模型匹配可能使用的模型**：
- **wan2.7-image**：图片生成模型
- **wan2.7-image-pro**：专业版图片生成模型
- **gpt-image-2**：GPT图片生成模型
- **claude-sonnet-4**：文本理解模型（可能用于风格匹配）

---

### 3️⃣ 匹配流程（PRD推测）

```
┌─────────────────────────────────────────────────────────────┐
│  1. 提取上下文变量                                            │
│     - seller_id (建议配置)                                   │
│     - stage (应用环节: 搭配/视觉/套图)                        │
│     - scene (应用场景: 主图素材/种草素材)                     │
│     - model (AI模型选择)                                     │
│     - targetMatchCount (目标匹配数量)                        │
└─────────────────────────────────────────────────────────────┘
                            ↓
┌─────────────────────────────────────────────────────────────┐
│  2. 查询商家正在使用的模板包                                  │
│     - 条件: seller_id + stage + scene + status=IN_USE       │
│     - 如果 seller_id 为空，查询全量模板包                    │
└─────────────────────────────────────────────────────────────┘
                            ↓
┌─────────────────────────────────────────────────────────────┐
│  3. 解析模板内容                                              │
│     - 遍历所有模板包                                         │
│     - 反序列化 templateContent (JSON)                        │
│     - 仅取 auditStatus=APPROVE 的模板                       │
└─────────────────────────────────────────────────────────────┘
                            ↓
┌─────────────────────────────────────────────────────────────┐
│  4. 查询店铺基因（基于 seller_id）                            │
│     - 店铺风格偏好                                           │
│     - 历史匹配记录                                           │
│     - 商家活跃模板包                                         │
│     - 如果 seller_id 为空，跳过此步骤                        │
└─────────────────────────────────────────────────────────────┘
                            ↓
┌─────────────────────────────────────────────────────────────┐
│  5. 调用AI模型进行匹配                                        │
│     - 输入：店铺基因 + 模板特征                              │
│     - 输出：匹配度评分 + 排序                                │
│     - 耗时：30-60秒                                          │
└─────────────────────────────────────────────────────────────┘
                            ↓
┌─────────────────────────────────────────────────────────────┐
│  6. Tair 疲劳度检查                                           │
│     - 检查每个模板的使用次数 (Tair 计数器)                   │
│     - 过滤掉使用次数 >= maxUseCount 的模板                  │
│     - 如果全部超限 → 清除所有计数，重新使用全部模板          │
└─────────────────────────────────────────────────────────────┘
                            ↓
┌─────────────────────────────────────────────────────────────┐
│  7. 截断                                                      │
│     - 取 top targetMatchCount 个模板                        │
└─────────────────────────────────────────────────────────────┘
                            ↓
┌─────────────────────────────────────────────────────────────┐
│  8. 使用计数递增                                              │
│     - Tair 计数器 +1 (TTL=24小时)                          │
└─────────────────────────────────────────────────────────────┘
                            ↓
┌─────────────────────────────────────────────────────────────┐
│  9. 输出结果                                                  │
│     - matched_template_ids: 匹配的模板 ID 列表              │
│     - matched_template_used_ids: sellerId_pkgId_templateId  │
│     - matched_template_pkg: 模板包 ID                       │
│     - matchedImg: 匹配的模板图片 URL 列表                   │
└─────────────────────────────────────────────────────────────┘
```

---

### 4️⃣ 与规则匹配的核心差异

| 差异点 | 规则匹配 | 模型匹配 |
|--------|---------|---------|
| **排序逻辑** | 手动配置 matchTypes 列表 | AI模型自动排序 |
| **类目过滤** | 根据 taoCate 过滤 | AI模型可能自动处理 |
| **季节过滤** | 根据 seasonTag 过滤 | AI模型可能自动处理 |
| **风格过滤** | 根据 styleTags 过滤 | AI模型可能自动处理 |
| **seller_id** | 模板包模式必填 | PRD定义为可选 |
| **性能** | 快速（毫秒级） | 较慢（30-60秒） |
| **可解释性** | 高（规则清晰） | 低（黑盒） |

---

### 5️⃣ seller_id 的作用（PRD定义）

```
模型匹配模式：
1. seller_id 为可选字段（PRD定义）
2. 建议配置 seller_id，用于查询店铺基因
3. 店铺基因用于优化AI匹配算法
4. 但匹配时不会根据 seller_id 去强校验
   - 不会报错："seller_id 不匹配"
   - 而是优先匹配该商家的模板
5. 如果 seller_id 为空，匹配全量模板
```

**与规则匹配的区别**：

```javascript
// 规则匹配 × 模板包
if (!seller_id_configured) {
  throw new Error("该策略中包括模板匹配，但策略入参中没有商家ID");
}

// 模型匹配
if (!seller_id_configured) {
  // 不报错，但匹配质量可能下降
  log.warn("seller_id 未配置，将匹配全量模板");
}
```

---

### 6️⃣ 不支持的字段

**模型匹配不支持以下字段**：

```
❌ 排序维度（matchTypes）
   - 原因：由AI算法自动排序
   - 规则匹配：支持 cate、season、style、ctr

❌ 硬匹配字段（mustMatchFields）
   - 原因：AI模型自动处理匹配逻辑
   - 规则匹配：支持 seller_id、match_cate、match_season
```
